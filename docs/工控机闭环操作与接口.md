# 工控机闭环操作与接口

适用：两仓 `feature/independent-control-v2` 配套版本。两端 API 为 1；Tenco 配置、地图和作业文件升级到 schemaVersion=2。完整设计见 [总体方案](develop/工控机闭环系统总体方案V3.md)，本页描述实际操作和当前实现。

## 1. 控制职责

Tenco 负责地图编辑、寻路、整项任务编译、静止示教、任务下发和监视。路线、单垄往返、多垄任务均编译为 follow_path / turn / wait 步骤，由工控机一次接收并校验。Pure Pursuit、速度规划、路径进度、停车及循环全部在 tracking_node 执行。上位机已删除 RouteFollower、RowWorkClient 和本地自动速度链路。

手动按钮和键盘仍经 MotionCommandArbiter → ChassisClient → 底盘 WebSocket。手动直接发送既有 cmd_vel，不申请许可，不调用任务服务。自动使用另一条 WebSocket 连接发送相同格式，两路独立，不增加仲裁。现有 Lua 脚本不修改。

## 2. 配置和首次使用

1. 配置 `poseSource.baseUrl=http://<工控机>:18131/api/v1`、`tracking.baseUrl=http://<工控机>:18130/api/v1`；手动 `network.websocketUrl` 保持直连底盘。`network.authToken` / 环境变量 `TENCO_AUTH_TOKEN` 用于 HTTP 和手动 WS 认证。
2. 工控机的共享配置提供原点、车辆标定、定位误差界限和场地安全参数；本车轮距 0.25 m、左右轮径 0.20 m、轮端 ticks/rev=65536。维护页只读回显这些信息；上位机不保存第二套轮距、轮径或 PP 参数。
3. 在地图页“获取任务操作权”。确认 fusion、tracking 与底盘反馈新鲜，读取原点和标定版本。
4. “确认地图坐标与原点”：核对地图与 ENU 的平移和旋转。历史地图轴为南/东，适配器先换成东/北再施加经实测确认的刚性变换。不能仅因地图看起来接近就确认。
5. 规划路线，或停稳后采集单垄起终点；多垄任务可组合 RowLeg、Transfer、Turn、Wait。设置速度、容差、检查点停留与拍摄；选择工控机已核实的通道和转向区域 ID。
6. 上传整项计划，等待 Ready。上传不开始运动。“读取任务”用于核对任务 ID、版本、步骤数和摘要。
7. 明确点击启动。上位机提交带短时请求凭据的 start；工控机自行校验任务、定位、连接及实测停稳。启动不清除手动输入，也不要求上位机手动底盘连接在线。

地图、任务参数、原点或标定变化后，旧准备结果失效，需要重新上传。循环任务的末端必须连接起点；往返任务通过原地转向后正向行驶实现。旧文件保留原请求容差（例如 0.15 m），并要求重新确认坐标；它不代表已经满足新精度目标。

## 3. 运行与异常恢复

- 暂停保留进度，显式恢复前重新确认坐标、停稳和请求有效性。中止结束当前 execution；再次作业重新准备计划。
- 手动输入只影响本通道；自动运行不检查手动操作。连接恢复不重放旧速度，自动故障恢复仍需显式任务操作。
- 首页停止只清除手动输入并发本通道零速；任务页停止只向 tracking 发 estop，使自动任务故障并发零速。任务复位不开始运动，不表示底盘硬件锁存或解除锁存。
- 操作会话每 200 ms 续约、1 s 超时，运动许可最长 500 ms。会话只保护后续任务写操作，过期不暂停正在执行的自动任务；网络恢复不会自动 start/resume。
- HTTP 写入超时可能已经被服务端执行。客户端通过原 requestId 查询命令结果，不重发运动操作。界面显示“结果未知”时先核对工控机当前执行状态。
- fusion/tracking 重启更换 bootId，底盘 WebSocket 重连更换工控机本地 connectionId；旧位姿、示教结果及相关请求失效。tracking 将未完成执行记为 Aborted/interrupted，重启不自行运动。
- 关闭程序前可取消未保存文件对话框；确认退出后停止本地客户端及手动发送，已启动自动任务继续在工控机执行。包含拍照 external_ack 的步骤仍需要外部业务确认，离线时等待并按步骤超时处理。

## 4. 检查点拍摄

停车及停留由工控机完成。启用拍摄的检查点产生 `external_action_requested`（reason=capture）事件，保持 Waiting；Tenco 的 ExternalEventCoordinator 只处理业务拍摄和事件确认，不生成运动速度。

相机调用 `POST /camera/photo`，期望 `{ "success": true, "path": "..." }`。调用前先原子写入事件 intent，拍摄成功先保存结果再发送 ack。记录位于 Qt AppLocalDataLocation 下 `checkpoint-actions`，文件名为事件 ID 的 SHA256；最多 4096 条，达到上限后停止新拍摄并提示归档。不要删除未完成任务记录。

照片响应丢失、程序在拍摄中退出、事件缺页或结果未知时不会自动重拍。核查相机实际文件后，使用“人工核对检查点拍摄结果”确认成功或失败；确认绑定对话框打开时的事件 ID，不能误确认随后出现的其他事件，也不能覆盖已确定结果。暂停中可以确认，但车辆继续等待显式恢复。

示教采样失败或请求结果未知时不生成示教点；确认停稳后可重新采样。采样结果必须匹配 fusionBootId，服务重启不能复用旧 captureId 的结果。

## 5. HTTP 接口

下列路径相对于 `/api/v1`。写操作使用 Bearer 认证；tracking 操作同时要求 `X-Operator-Token`，全局 estop 不依赖操作会话。生产非回环监听必须配置认证。请求体最大 1 MiB；重定向禁止。64 位序号字段使用十进制字符串，禁止用 JSON 浮点数传输。

| 服务 | 方法和路径 | 用途 |
|---|---|---|
| fusion :18131 | GET /health、/pose | 权威 ENU/base_link 控制位姿与健康 |
| fusion | POST /captures；GET /captures/{captureId} | 有界异步静止采样、独立观测数和离散度 |
| tracking :18130 | GET /health、/configuration、/status | 配置版本、就绪条件和任务快照 |
| tracking | POST /sessions、/sessions/{sessionId}/heartbeat | 操作会话和短时运动许可 |
| tracking | POST /tasks；GET /tasks/{taskId}?revision=1 | 整项计划上传、持久化和回读 |
| tracking | POST /control | start/resume/pause/abort/estop/reset_fault |
| tracking | GET /commands/{commandId} 或 /commands?requestId=... | 确定写入最终结果 |
| tracking | GET /events?after=...；POST /events/{eventId}/ack | 事件补读和业务结果确认 |
| tracking | GET /executions/{executionId} | 历史结果与中断记录 |
| tracking | GET /origin；POST /origin | expectedRevision 条件更新和 pending/active 原点 |

任务、标定和地图必须匹配 context 中 mapId/mapRevision/originRevision/frameTransformRevision/calibrationId/controllerProfileRevision。start/resume 还带 expectedStateVersion、motionPermit、validForMs。每次显式操作生成 requestId；同 ID 不同正文被拒绝。

pose 中 stateAgeMs、positionObservationAgeMs、headingObservationAgeMs 各自表达估计状态、真实绝对位置观测及航向观测的年龄。客户端加上网络往返和本地停留时间；高频重复预测不会刷新真实观测年龄。

原点更新先写 pending，fusion 停机/重启读取共享 origin 后，tracking 在停稳时确认 adoption 才显示 active。切换后旧计划失效；服务端没有自动重启 fusion 的远程命令。

## 6. 底盘 WebSocket 既有协议

手动和自动各自连接底盘，两端只发送：

```json
{"packet":{"cmd":"region","region":"cmd_vel","index":1},"msg":{"xvel":0.1,"yvel":0.0,"thetavel":0.0,"isRemote":true}}
```

`isRemote=true` 选择当前 Lua 的外部速度入口，不是上位机手动身份字段。无控制权申请、租约、epoch 或额外速度字段。IPC 在本地丢弃过期命令、只保留最新速度，连接变化后不回放旧命令；现有 Lua 接收超时逻辑保持原样。

任务状态使用 `controlChannels=independent`、`chassisConnected`、`chassisConnectionId`。后者只是本地连接标识。`measuredTwist` 来自融合编码器，包含 valid/ageMs/source=fusion-encoder；不伪造底盘控制权或锁存状态。Idle、Ready、Paused 和终态不会持续发布自动零速。

## 7. 本机测试和部署边界

Windows 不安装 WSL 也可构建 Qt 程序和 standalone C++ 服务。固定 Qt 6.5.3/MinGW Kit 构建后运行：

```powershell
ctest --test-dir build/ipc-task-client-v1-Qt6.5.3-Debug --output-on-failure
python tests/run_ipc_integration.py --ipc-source ../src --server ../src/build/control-windows/tracking_sim_server.exe --client build/ipc-task-client-v1-Qt6.5.3-Debug/tenco_ipc_client_probe.exe
python tests/run_gui_smoke.py --app ../bin/Tenco.exe --output build/gui-smoke-ipc
```

GUI 冒烟模式仅在测试构建启用，使用显式回环配置并关闭设备服务，截图覆盖首页、三个任务页、缩放、维护、帮助和关于。完整 ROS 四包构建、消息转换及 EKF 回归由 Linux Humble CI 验证。

Jetson 实际型号、JetPack/Ubuntu/ROS、底盘固件和现场标定仍须实测。IPC 仓库 deployment 提供目标环境盘点、构建、配套 SHA256 清单、systemd、升级和回退。Windows/CI 测试不能代替 ARM64 部署、驱动联调、停止时延及独立路径精度验收。
