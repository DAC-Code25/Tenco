## 当前测量结论

当前现场相机预览为640×480@15、JPEG质量70，已被用户保存为settings revision6；本轮保留。单路MJPEG平均每帧约42.4KB，正常交付15FPS时HTTP内容约 **5.13Mbps / 0.64MB每秒 / 2.31GB每小时**。同一服务本机10秒测量153帧、间隔FPS15.18、内容5.18Mbps；初始无线15秒测量226帧、内容5.13Mbps。

Mbps是每秒百万比特，MB/GB按十进制换算；这些数字是multipart内容，未含TCP/IP、确认、无线协议和重传。照片、H.264录像保存在工控机Capture，上位机只发送控制并接收JSON结果，不会自动将原生照片或720p录像传回，所以原生采集/录像数据率不等于无线业务流量。

IP层只读抓取一次无线视频连接：15.2756秒，发送5735包、接收870包，共6605包，约 **432.39 IP包/秒、双向4.50Mbps**。该轮实际交付仅12.95FPS，不能与另一轮15FPS内容量混作同一测量。样本未见大于MTU1500的offload包；包含TCP确认/重传，不等于802.11空口帧数或重试次数。视频达到15FPS时，按每帧长度/MTU估计数据包约450包/秒，确认等开销另计；这里只是估算，不是本轮完整上位机实测。

**不能将网卡144.4Mbps连接速率当作稳定可用带宽。** 本轮两端同接2.4GHz/channel1/802.11n热点，信号约-43～-45dBm；实际无线交付曾15FPS，后续5秒只有8帧/间隔1.56FPS，再次与工控机本机同时10秒对比：工控机本机15.18FPS，上位机无线3.57FPS。相机持续健康/新帧、revision6未变，说明传输链存在波动；不能把低流量时的丢帧当作流量优化成功。

用户操作、任务上传、诊断、重连和其他程序另计。所有服务正常且没有新事件时，任务事件优化可以少至每分钟300次空HTTP查询；不能把5次/秒描述成5个IP包/秒，一次HTTP可能包含多个数据包、建连和挥手。旧服务若缺少可选lastEventSeq，继续原事件轮询，避免失去事件功能。

## 已实现的优化及使用边界

Tenco减少已追平事件查询和离线metadata请求；任务状态/位姿/手动/云台保护频率保持。新上位机已在本工作空间构建，运行配置已校验恢复，未自动启动现场上位机。

工控机相机候选使用JPEG优化Huffman表，质量/像素/尺寸/帧率不变，multipart头/JPEG/结尾用MSG_MORE合并发送。Jetson OpenCV4.8同一现场JPEG解码得到的BGR重新编码对比：42505→40791B，减少4.03%，两份编码的解码像素最大差0；编码P50为3.16→5.19ms、P95为3.22→5.38ms。该结果是同输入编码基准，不是已上线流量降幅，也不保证其他场景同样比例。新增status.previewJpegOptimized与启动回退选项，照片JPEG90/录像H264和媒体settings不改。

相机候选已在目标机隔离Release构建/CTest5/5，尚未切换在线程序；完整部署阶段见 [相机开发记录](../../oak-camera-service/docs/develop/无线预览传输优化开发记录.md)。本轮不自动调整网络、SSID、路由、无线节能或服务配置。只减少几个百分点的编码体积不能保证消除当前无线卡顿。

## 进一步减少延迟和流量

1. 优先比较稳定5GHz网络；工控机可用网线接同一AP，上位机无线，减少双端无线中转的空口占用。两个无线终端经AP互传涉及双程空口转发；2.4GHz环境共享/干扰/热点调度会影响尾延迟，即使RSSI良好也可能卡顿。不能仅凭本轮样本断言具体干扰源。
2. 同时只打开必要的视频预览，关闭额外浏览器/测试拉流；测量器本身也会新增一条流。录像在工控机本地保存，不需要额外拉一份录像流。
3. 当前“配置维护→视频与相机→工控机媒体参数”的预览尺寸/FPS已经可以调节，与照片/录像独立。如果接受预览清晰度/流畅度取舍，可显式调整；本轮不替用户降低它们，也不改保存规格。
4. 若需显著降低相同尺寸/FPS的视频传输量，需要另做H.264等帧间编码的预览通道与上位机解码/重连/兼容回退。现有录像H.264不等于预览已有H.264；本轮没有实现或声称上线该能力。

## 可重复的只读测量

建议先停止首页预览再运行，避免测量期间形成两份视频流。该脚本只GET拉流，不拍照、录像、改设置、重启或发送运动；输出不含原始图像。

```powershell
python Tenco/scripts/measure_camera_traffic.py --url http://192.168.31.13:18080/camera/stream.mjpeg --seconds 15
```

工控机也可运行同一Python脚本，将URL改为127.0.0.1；同时对比可帮助区分本机出帧与无线交付。cadenceFps使用相邻完整帧到达间隔，应用流量包括首个缓存帧；样本很短时帧数/总时长和间隔FPS会有差异。网络异常/不完整JPEG明确报错，不把失败当作低带宽达标。
