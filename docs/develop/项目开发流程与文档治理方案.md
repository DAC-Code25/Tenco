# 项目开发流程与文档治理方案

## 1. 基本信息

- 方案日期：2026-08-29
- 开发分支：`docs/development-governance-v1`
- 基线分支：`master`
- 基线提交：`d9121a3`
- 改动类型：开发流程治理、构建环境固化、文档重命名

## 2. 背景与现状

当前项目已经具备 CMake 模块化构建、Qt Test/CTest 测试入口、GitHub Actions 和多份专题开发方案，但仍有以下治理问题：

1. 根目录缺少可被开发代理稳定读取的完整项目工作规范。
2. `docs/07_Dev_Workflow.md` 中的分支、提交和评审要求仍是建议性质，未覆盖修改前基线检查、同步、独立分支、方案门禁和开发记录。
3. `docs/02_Build_and_Run.md` 使用 Qt 6.8.3 作为示例，没有固化当前 Qt Creator 已验证的 Qt 6.5.3 MinGW 64-bit Debug Kit。
4. `docs/develop/` 下专题方案使用英文文件名，查找、引用和长期维护不够直观。
5. 根目录遗留的 `implementation_plan.txt` 没有归档到统一的开发方案目录。

本次开始前已确认工作区干净，原功能分支内容已合并到远程 `master`；本地 `master` 已快进到远程最新提交，再创建独立文档分支。

## 3. 目标

1. 新建 `AGENT.MD`，把代码修改前、开发中、验证后、提交推送和 PR 交付的要求固化为强制流程。
2. 新建兼容入口 `AGENTS.md`，确保识别标准文件名的开发工具也会读取并遵循 `AGENT.MD`。
3. 规定每个新增功能、功能改进、重构和缺陷修复必须分别建立新的中文方案文档和新的中文开发记录文档。
4. 固化 Qt Creator 截图中的构建环境，并明确 CMake 项目测试开关。
5. 将现有开发方案统一改为中文文件名，更新所有仓库内引用，不改变任何业务行为。
6. 更新现有开发流程、构建说明和文档索引，使人工流程与代理规范保持一致。

## 4. 设计原则

- 最小化修改：只改治理文档、文档路径引用和必要的帮助页资料路径，不改业务逻辑。
- 稳定性优先：先检查 Git 基线，再同步远程和创建独立分支；禁止带着不明修改切换分支或开始新任务。
- 可追溯：方案、记录、分支、日期、提交、推送和 PR 信息互相关联。
- 可验证：每次改动完成后必须按固定 Kit 完成 CMake 配置、完整构建和 CTest；涉及现场设备或 GUI 时再补充对应手工测试。
- 不影响无关模块：文档路径变更后全仓检索旧路径，防止帮助页和索引产生失效引用。
- 中文交付：Commit 标题、PR 标题和 PR 描述全部使用中文；类型前缀可以保留 `feat`、`fix`、`docs` 等通用标识，但说明正文必须为中文。

## 5. 修改范围

### 5.1 代理规范

- `AGENT.MD`：完整规则的唯一事实来源。
- `AGENTS.md`：标准文件名兼容入口，只负责引导工具读取 `AGENT.MD`，避免维护两份重复规则。

规范至少覆盖：

1. IDE 未保存缓冲区提醒与 Git 工作区检查。
2. 既有修改的保护、验证、中文提交、推送和 PR 处理。
3. 远程默认分支同步与每任务独立分支。
4. 修改前必须先建立方案文档。
5. 每次任务必须建立独立开发记录。
6. 最小改动、性能、稳定性、可靠性、兼容性和无关模块保护。
7. 固定构建、测试、方案符合性检查与失败后闭环修复。
8. 中文提交与中文 PR 描述模板。

### 5.2 固定构建配置

以用户提供的 Qt Creator 配置为准：

- 源码目录：`D:/QTProject/Tenco`
- 构建目录：`D:/QTProject/Tenco/build/Desktop_Qt_6_5_3_MinGW_64_bit-Debug`
- Qt：`D:/Qt/6.5.3/mingw_64`
- Kit：Desktop Qt 6.5.3 MinGW 64-bit
- C 编译器：`D:/Qt/Tools/mingw1120_64/bin/gcc.exe`
- C++ 编译器：`D:/Qt/Tools/mingw1120_64/bin/g++.exe`
- 生成器：Ninja
- 构建类型：Debug
- `BUILD_TESTING=ON`
- `TENCO_BUILD_TESTS=ON`
- QML 调试：启用，配置时保留 `-DQT_QML_DEBUG`

其中 `BUILD_TESTING` 控制 CTest 总入口，`TENCO_BUILD_TESTS` 是项目自身测试开关，两者必须同时开启。

## 6. 实施步骤

1. 创建本方案，确认修改范围和验收标准。
2. 新建 `AGENT.MD` 和 `AGENTS.md`。
3. 重命名全部既有开发方案并更新引用。
4. 更新 `docs/README.md`、`docs/02_Build_and_Run.md` 和 `docs/07_Dev_Workflow.md`。
5. 新建本次开发记录，并根据实际执行结果持续更新。
6. 全仓检查旧文件名、无效引用、格式错误和非预期业务代码差异。
7. 按固定 Qt 6.5.3 Kit 重新配置、构建并运行全部 CTest。
8. 对照本方案逐项复核；失败时修复并重新验证。
9. 使用中文提交说明提交，推送新分支，并提供中文 PR 标题和完整描述。

## 7. 影响分析

### 7.1 性能

不修改运行时算法、线程、网络或数据路径，预期无性能影响。

### 7.2 稳定性与可靠性

通过强制基线检查、独立分支、构建测试和记录闭环，降低混入旧修改、基线过期、构建环境丢失和无验证提交的风险。

### 7.3 兼容性

- Git 支持 UTF-8 中文路径；项目源码和文档统一按 UTF-8 保存。
- 帮助页中引用的方案路径将同步修改，并通过编译验证 UTF-8 字面量。
- 同时保留 `AGENT.MD` 和标准入口 `AGENTS.md`，兼容不同开发代理的文件名识别方式。

### 7.4 无关模块

不修改底盘控制、地图算法、视频、网络、数据库、日志和 UI 业务实现。唯一涉及 `.cpp` 的修改是帮助页内文档路径字符串更新。

## 8. 验证与验收

### 8.1 静态检查

- `git diff --check` 无空白或补丁格式错误。
- `rg` 检索不到已迁移的英文方案文件名。
- `docs/develop/` 下方案文件名符合中文命名要求。
- 仓库内所有方案引用均指向真实文件。
- `AGENT.MD` 覆盖用户要求的全部流程门禁。

### 8.2 固定环境构建

使用以下配置等价命令验证 Qt Creator Kit：

```powershell
$env:PATH = 'D:/Qt/6.5.3/mingw_64/bin;D:/Qt/Tools/mingw1120_64/bin;D:/Qt/Tools/Ninja;' + $env:PATH

D:/Qt/Tools/CMake_64/bin/cmake.exe `
  -S D:/QTProject/Tenco `
  -B D:/QTProject/Tenco/build/Desktop_Qt_6_5_3_MinGW_64_bit-Debug `
  -G Ninja `
  -DCMAKE_BUILD_TYPE=Debug `
  -DBUILD_TESTING=ON `
  -DTENCO_BUILD_TESTS=ON `
  -DCMAKE_MAKE_PROGRAM=D:/Qt/Tools/Ninja/ninja.exe `
  -DCMAKE_PREFIX_PATH=D:/Qt/6.5.3/mingw_64 `
  -DCMAKE_C_COMPILER=D:/Qt/Tools/mingw1120_64/bin/gcc.exe `
  -DCMAKE_CXX_COMPILER=D:/Qt/Tools/mingw1120_64/bin/g++.exe `
  -DCMAKE_CXX_FLAGS=-DQT_QML_DEBUG

D:/Qt/Tools/CMake_64/bin/cmake.exe `
  --build D:/QTProject/Tenco/build/Desktop_Qt_6_5_3_MinGW_64_bit-Debug `
  --parallel

D:/Qt/Tools/CMake_64/bin/ctest.exe `
  --test-dir D:/QTProject/Tenco/build/Desktop_Qt_6_5_3_MinGW_64_bit-Debug `
  --output-on-failure
```

若实际 Qt 安装中的 CMake/Ninja 可执行文件位置与示例不同，只允许调整工具可执行文件位置，不允许改变 Qt 版本、编译器、生成器、构建类型、测试开关和构建目录。

命令行必须先注入 Qt、MinGW 和 Ninja 的运行时目录；Qt Creator 会自动提供 Kit 环境，普通 PowerShell 不会。缺失时 CTest 可能统一返回 Windows `0xc0000135`，这属于测试进程依赖加载失败，并非测试断言失败。

### 8.3 验收标准

- CMake 配置成功。
- Tenco 主程序和全部测试目标构建成功。
- CTest 全部通过。
- 方案要求均已实现，开发记录内容完整。
- Git 提交和 PR 交付内容使用中文。
