# 独立控制通道与车辆参数统一开发方案

- 日期：2026-09-18
- 类型：用户确认的架构修订与配置统一
- 开发分支：feature/independent-control-v2
- 需求依据：本次对话明确要求不修改 Lua；手动无需许可、直接通过旧 WebSocket 发送；自动不依赖上位机在线和手动操作；不实现两路竞争仲裁。
- Git 基线：最新默认分支同步后在新分支快进承接上一轮已交付提交；Tenco 37478db，IPC 00784f4。原 PR 未合并，不修改默认分支。

## 目标、接口及验收

1. 本车轮距 0.25 m，左右轮径 0.20 m，轮端 ticks 65536（底盘脚本已除减速比 25）。现场模板、本车仿真与融合后备配置一致；共享标定仍为入口。几何值由用户指定，其余现场标定/场地信息不得伪填为已验证。
2. 两端均发送既有 packet.cmd=region、region=cmd_vel、index=1，msg 只含 xvel/yvel/thetavel/isRemote。手动沿用 isRemote=true；自动也使用现有外部速度入口 isRemote=true，不依赖未实现的自动准入扩展。
3. 底盘连接只表达 WebSocket 连接状态；删除 tenco-control-v1、owner/epoch、许可交接、能力文件及相关运行依赖。保留最新命令槽、发送截止期、积压/断线处理，禁止重连回放旧速度。
4. tracking 从 ControlPose.measuredTwist 获取编码器实测速度及年龄。连接断开、反馈过期、定位失效、控制周期超期、存储故障和进程重启仍按本机状态机处理。软件停止是本通道零速与任务故障，不声称底盘硬件锁存。
5. 任务 HTTP 操作会话、请求去重、短时启动请求校验继续有效，但会话到期不再暂停已启动任务。Tenco 退出只停止本机客户端，不发送任务暂停。手动输入不调用任务操作，任务启动不清除手动输入。
6. 当前需要上位机执行的拍照事件仍为显式外部步骤，离线时等待并按步骤超时处理；普通行驶、转向、定时等待和循环不依赖上位机。此次不迁移相机业务。
7. script 全部文件 SHA256 与变更前相同；不连接真实设备或下发实车命令。

## 方案选择及影响

直接替换旧互锁实现；不增加兼容开关或双套底盘协议。相对模拟旧控制权返回，此方案避免虚构设备能力；相对修改 Lua，此方案符合用户边界。
两路同时发送的相互影响按用户约定不处理，不宣称手动优先。请求授权只保护任务 API，不保护手动速度、不维持任务运行。定位/标定/场地准备要求保持独立。
控制线程仍有界且不做网络等待，网络对象由各自事件循环拥有并取消、排空异步回调。零速只在本通道停止事件发出，空闲不定时发布零速。
地图/任务几何、PP 算法和视频数据库模块不重构。失联停车依赖现有底盘脚本的实际行为，部署记录不将本地过期丢弃描述为底盘 TTL。
回退使用本次两个基线提交及匹配配置；不改写 Lua 或旧分支。
