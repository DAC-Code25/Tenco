# Tenco 首页云台控制开发方案

## 1. 当前结论

首页已有 6 个云台控制按钮：

- `pushButton_3`：`UP`
- `pushButton_4`：`DOWN`
- `pushButton_5`：`左旋`
- `pushButton_6`：`右旋`
- `pushButton_7`：`上仰`
- `pushButton_8`：`下俯`

当前目标仍然是把这 6 个按钮接入云台升降、水平旋转、俯仰控制。但根据现场联调结果，原先计划的 `0x2b0 + tcp.lua + U/X/F` 字符串目标值控制链路不能直接作为第一版实现依据。

原因：

- `0x2b0` 字符串事件写入链路表现不稳定，单次/低频写入时控制器表值可能不变化。
- 通过 Lua 路径发送 `X200|F150` 曾导致水平舵机超过实际机械可旋转角度并在极限处卡住抖动。
- 控制器重启后仍可能保留或恢复上次危险目标状态，说明该链路存在残留目标/自动恢复执行风险。
- 在未确认真实机械限位、方向映射和底层停止机制之前，不能把首页按钮直接接到目标值命令。

因此当前方案调整为：

1. 第一阶段只做 PLC 状态读取、控制映射确认、安全停止能力确认。
2. 第二阶段封装上位机云台控制客户端。
3. 第三阶段在完成限位标定后，绑定首页按钮。

当前进度：

- 第一阶段已完成。
- 第二阶段已完成。
- 第三阶段已完成，Qt Creator 编译运行和现场点动验证已基本通过。
- 已完成键盘快捷键绑定和方向键专用拦截，避免误触发顶部菜单切换。
- 已完成升降轴持续动作逻辑：按住持续升降，松开、急停、软限位或反馈异常时停止。

## 2. 已确认的现场事实

### 2.1 网络与设备

- PLC Modbus TCP 地址：`192.168.31.120:502`
- Modbus Unit/Slave ID：`0xFF`
- 上位机可以直接访问 PLC。
- 小车控制器地址仍为：`192.168.31.7`
- 工控机相机服务地址为：`192.168.31.13`

### 2.2 可靠状态寄存器

当前已确认 `holding registers 100..106` 可以稳定读取云台/底盘状态：

```text
100 = 设备状态，1 表示就绪
101 = 云台高度，int16，有符号值
102 = 水平角度
103 = 俯仰角度
104 = 底盘 X 轴运动状态
105 = 底盘 Z 轴运动状态
106 = 目标速度
```

示例：

```text
[1, 65528, 134, 181, 0, 0, 0]
```

解释：

- `state = 1`
- `height = 65528`，按 int16 解释为 `-8`
- `yaw = 134`
- `pitch = 181`

高度字段需要按 signed int16 解释：

```text
65528 -> -8
65527 -> -9
65530 -> -6
65533 -> -3
65534 -> -2
0     -> 0
```

### 2.3 遥控测试观察

遥控测试时：

- 俯仰运动会改变 `holding 103`
- 水平旋转会改变 `holding 102`
- 升降运动会改变 `holding 101`
- `holding 0..29` 在遥控运动过程中未观察到稳定变化
- `coil 9/10/11/13` 在无明显云台位移时也会周期跳变，不能直接判定为云台方向控制位
- `coil 14` 曾在升降动作附近变化，但仍需进一步确认是否为升降相关状态或控制位

### 2.4 最新遥控观察结论

`--watch` 输出显示，coil 位存在明显周期性跳变：

```text
coil 9: False -> True
coil 10: True -> False
coil 11: False -> True
coil 13: False -> True
```

但这些跳变在 `height/yaw/pitch` 未变化时也持续出现，因此当前判断：

- `coil 9/10/11/13` 更像 PLC 内部周期状态、心跳、互锁状态或其它逻辑位。
- 不能因为它们在遥控时变化，就直接把它们当作控制输出。
- 后续测试应默认只观察 `holding 100..106`，只有需要排查底层状态时才打开 coil 输出。

可靠判断控制映射时，以 `height/yaw/pitch` 的实际变化为准，不以 coil 跳变本身为准。

### 2.5 现场软限位标定结果

通过遥控器分别操作到各轴极限位置，当前测得：

```text
初始状态：
height=-10, yaw=53, pitch=187

俯方向极限：
pitch=270

仰方向极限：
pitch=90

水平左旋极限：
yaw=180

水平右旋极限：
yaw=0

上升极限：
height=6126

下降极限：
height=-1984
```

因此第一版上位机软限位建议按保守值配置：

```text
height: -1900 .. 6000
yaw:       5 .. 175
pitch:    95 .. 265
```

说明：

- 不直接使用物理极限值，必须留安全余量。
- 首页按钮控制前，所有命令都必须先经过这些软限位。
- 后续如机械安装或零位变化，需要重新标定。

### 2.6 已验证但不能直接上线的写入方式

曾测试：

```text
write holding registers 0..5 = [0, 1, 0, 0, 0, 0]
```

结果：

- 读回 `holding 0..5` 可看到写入值。
- 但云台机构没有动作。

这说明：

- `holding 0..5` 可写不等于可控。
- PLC 内部真实控制触发条件可能还依赖 coil、状态机、使能位、边沿触发或其它控制表。

### 2.7 现场控制寄存器初步确认结果

通过短脉冲写 `holding 0..2`，当前已确认：

```text
holding 1 = 俯仰方向控制
  value 1: pitch 增大，趋向俯方向，极限约 270
  value 2: pitch 减小，趋向仰方向，极限约 90

holding 2 = 水平方向控制
  value 1: yaw 减小，趋向右旋方向，极限约 0
  value 2: yaw 增大，趋向左旋方向，极限约 180
```

测试记录：

```text
初始：height=4660, yaw=102, pitch=205

holding 1 = 1, 80ms:
pitch 205 -> 208

holding 1 = 2, 80ms:
pitch 208 -> 205

holding 2 = 1, 80ms:
yaw 102 -> 98

holding 2 = 2, 80ms:
yaw 98 -> 102
```

`holding 0` 已通过 `200ms` 短脉冲复测确认为升降方向控制：

```text
holding 0 = 1, 200ms:
height 4664 -> 4676

holding 0 = 2, 200ms:
height 4676 -> 4664
```

最终控制映射：

```text
holding 0 = 升降方向控制
  value 1: height 增大，上升
  value 2: height 减小，下降

holding 1 = 俯仰方向控制
  value 1: pitch 增大，趋向俯方向，极限约 270
  value 2: pitch 减小，趋向仰方向，极限约 90

holding 2 = 水平方向控制
  value 1: yaw 减小，趋向右旋方向，极限约 0
  value 2: yaw 增大，趋向左旋方向，极限约 180
```

## 3. 原 Lua 链路分析

### 3.1 Lua 链路形态

`tcp.lua` 的主要逻辑是：

1. 周期读取控制器表地址 `0x2b0`
2. 解析 `U/X/F` 字符串
3. 读取 PLC 当前反馈值
4. 根据目标值和当前值计算方向
5. 周期写 PLC 控制值
6. 达到阈值后停止动作
7. 写 `0x390` 作为执行记录
8. 释放 `0x2b0` 为 `freeidle`

### 3.2 当前不再推荐直接使用的原因

这条链路曾被认为适合上位机接入，但现场测试后需要降级为“参考资料”，不能作为第一版稳定控制接口。

主要风险：

- `0x2b0` 事件接收不稳定，低频/单次发送可能不触发。
- 目标值闭环缺少可靠的软件限位。
- 目标值超过机械极限时会持续驱动，导致舵机卡死抖动。
- 控制器重启后仍可能恢复危险目标或状态。
- `X/F` 与实际水平/俯仰字段在脚本内部变量命名上存在混乱，容易误操作。

结论：

- 暂停把 Qt 首页按钮接入 `0x2b0`。
- 不再直接发送 `X200|F150`、`U3000|X150|F150` 这类目标值命令。
- 只有在 Lua 脚本加入硬限幅、目标清除、超时停止、异常停止后，才允许重新评估这条链路。

## 4. 当前推荐架构

### 4.1 第一版架构

第一版采用“上位机直连 PLC 诊断 + 后续服务化封装”的路线：

```text
Qt 首页按钮
  -> GimbalControlClient
  -> 安全限位/节流/状态机
  -> PLC Modbus TCP 或工控机云台服务
  -> PLC
  -> 升降电机/水平舵机/俯仰舵机
```

控制映射确认后，当前项目侧已采用 `GimbalControlClient` 直接访问 PLC Modbus TCP：

- 状态读取：`holding 100..106`
- 升降控制：`holding 0`
- 俯仰控制：`holding 1`
- 水平控制：`holding 2`
- 停止控制：写 `holding 0..2 = 0`

### 4.2 后续推荐服务化形态

如果工控机/控制器侧后续可以新增服务，推荐把 PLC 控制封装为一个独立云台服务：

```text
GET  /gimbal/status
POST /gimbal/jog
POST /gimbal/stop
POST /gimbal/home
POST /gimbal/move
```

上位机只调用服务接口，不直接理解 PLC 寄存器。这样更符合企业级维护要求：

- PLC 协议集中在设备侧维护。
- 上位机只处理业务语义。
- 安全限位和急停逻辑靠近执行机构。
- 网络中断时设备侧可立即本地停止。

## 5. PLC 控制映射确认计划

### 5.1 禁止项

在完成限位标定前，禁止执行：

- 发送任意未限幅的 `U/X/F` 目标值。
- 发送超过当前附近小范围的水平/俯仰目标。
- 在首页按钮上直接绑定运动命令。
- 用高频点击代替稳定通信机制。
- 在机构靠近硬限位时继续测试方向命令。

### 5.2 允许项

当前允许做：

- 只读读取 `holding 100..106`
- 观察遥控器动作时各地址变化
- 手动清零已确认的安全控制输出
- 在机构远离硬限位时，用短脉冲测试单个候选控制位

### 5.3 控制映射确认顺序

推荐顺序：

1. 只读运行诊断脚本，确认状态读取稳定。
2. 手动用遥控器分别操作 6 个方向，记录变化的 holding、coil、input 地址。
3. 使用 `--clear --yes` 清理候选控制输出。
4. 选择一个候选地址做极短脉冲，例如 `100ms`。
5. 每次只测试一个方向。
6. 测试后立即读取 `100..106`，确认是否有位移。
7. 记录方向、地址、值、持续时间、状态变化。

### 5.4 安全脉冲原则

任何写入测试必须满足：

- 默认脉冲不超过 `100ms`
- 每次写入后自动清零
- 同一轴连续测试前必须确认机构没有靠近极限
- 如果状态值持续变化或机构抖动，立即断电或执行清零

- 支持单寄存器方向点动
- 支持 `holding 0..2` 同时清零停止
- 支持软限位
- 支持 1.5 秒点动超时自动停止，其中水平旋转和俯仰保留短超时保护，升降轴改为按住持续动作、松开或到软限位后停止
- 首页急停会同步停止云台
- 按钮只依赖云台配置启用，不再因为暂未收到状态而整组禁用

- 键盘快捷键已绑定到云台：
  - 上箭头 = 上升
  - 下箭头 = 下降
  - 左箭头 = 左旋
  - 右箭头 = 右旋
  - 左 `Ctrl` + 上箭头 = 上仰
  - 左 `Ctrl` + 下箭头 = 下俯
- 首页运行时通过主窗口事件过滤器优先截获这些云台按键，避免方向键被顶部导航按钮、焦点控件或 Qt 默认焦点移动逻辑抢走。
- 顶部导航按钮已设置为不接收键盘焦点，防止云台点动过程中误触发首页、地图、维护、帮助、关于之间的菜单切换。
- 键盘动作切换时会先清零旧轴再启动新轴，保证 PLC 的 `holding 0..2` 不残留上一个方向命令。

### 6.3 第三阶段：首页按钮绑定

当前已采用“按下点动、松开停止”：

```text
UP   -> holding 0 = 1，上升
DOWN -> holding 0 = 2，下降
左旋 -> holding 2 = 2，yaw 增大
右旋 -> holding 2 = 1，yaw 减小
上仰 -> holding 1 = 2，pitch 减小
下俯 -> holding 1 = 1，pitch 增大
释放 -> holding 0..2 = 0
急停 -> holding 0..2 = 0
```

选择点动模式的原因：

- 更符合首页 6 个方向按钮的语义。
- 松手即可停止，安全性高。
- 不依赖 `0x2b0` 字符串事件。

升降轴的现场使用逻辑：

- 按住 `UP` 或键盘上箭头时持续上升。
- 按住 `DOWN` 或键盘下箭头时持续下降。
- 松开按钮或按键后立即写 `holding 0..2 = 0` 停止。
- 到达配置软限位后立即停止。
- 运动中如果状态反馈读取失败，立即请求停止。

### 9.1 保留诊断脚本

推荐用仓库内诊断脚本。默认只看可靠状态，不打印 coil 噪声：

```powershell
python scripts\gimbal_plc_diag.py --watch
```

如果要给某次遥控动作打标签：

```powershell
python scripts\gimbal_plc_diag.py --watch --mark "pitch up"
```

只有在需要排查 PLC 内部状态时，才打开 coil 输出：

```powershell
python scripts\gimbal_plc_diag.py --watch --show-coils
```

只读观察稳定后，再执行显式清零：

```powershell
python scripts\gimbal_plc_diag.py --clear --yes
```

如果要测试候选 holding 控制寄存器，只允许短脉冲：

```powershell
python scripts\gimbal_plc_diag.py --pulse-holding 0 1 --duration-ms 100 --yes
```

如果要测试候选 coil 控制位，只允许短脉冲：

```powershell
python scripts\gimbal_plc_diag.py --pulse-coil 9 --duration-ms 100 --yes
```

注意：

- 脉冲命令必须在机构远离极限时执行。
- 每次只测一个地址。
- 一旦机构异常抖动，立即断电或执行 `--clear --yes`。
