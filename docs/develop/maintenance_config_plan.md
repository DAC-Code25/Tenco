# Tenco 维护界面配置管理开发方案

## 1. 目标

维护界面用于管理项目运行时基础配置，第一版重点覆盖：

- 底盘控制器通信地址
- 状态读取、写寄存器、地图保存接口
- 视频预览流和工控机相机控制地址
- 云台 PLC Modbus TCP 参数和软限位
- 直线/多垄作业服务地址
- 地图基准经纬度
- 路径跟踪关键控制参数
- 车辆标定参数
- 生产运行状态、配置文件路径和备份状态

维护界面不是单纯参数表，而是面向生产现场的维护入口。核心要求：

- 可看到当前程序实际使用的配置文件和运行目录。
- 可进行配置备份、恢复、加载和热应用。
- 可维护通信、视频、云台、路径跟踪和车辆标定等现场常改参数。
- 可避免误操作，例如未保存离开提示、滚轮误改参数保护、原子写配置。
- 对高风险参数保留校验和恢复手段，降低现场调错后无法回退的风险。

维护界面提供两种保存操作：

- `保存`：只写入 `config.json`，不影响当前运行中的模块。
- `保存并应用`：写入 `config.json` 后立即通知运行中模块热加载。

## 2. 当前实现

### 2.1 配置写回

`ConfigManager` 已新增：

- `ConfigSnapshot`
- `snapshot()`
- `saveSnapshot(snapshot, errorMessage, applyAfterSave)`
- `configChanged()`

保存时使用 `QSaveFile` 原子写入，避免写到一半导致 `config.json` 损坏。

`保存` 与 `保存并应用` 的行为分离：

- `保存`：先把表单内容写入 `config.json`，再回滚内存中的运行配置，不触发运行模块重连。
- `保存并应用`：写入 `config.json` 后保留内存中的新配置，并发出 `configChanged()` 通知运行模块热加载。

### 2.2 维护页 UI

维护页当前采用运行时动态构建 UI，不直接大规模修改 `mainwindow.ui`。

当前视觉结构：

- 顶部说明区：展示“运行配置维护”标题、功能说明和安全提示。
- 中间配置区：使用标签页切换配置类别，每个类别内部采用卡片式表单。
- 底部操作区：展示当前配置文件路径、保存状态，并提供 `加载配置文件`、`还原运行配置`、`恢复上次配置`、`保存`、`保存并应用`。

页面分组：

- `通信`
- `视频/相机`
- `云台`
- `直线作业`
- `定位/控制`
- `车辆标定`
- `生产维护`

每个分组放入可滚动区域，避免配置项增加后页面显示不全。输入控件、标签页和按钮使用维护页局部样式，不影响首页、地图等其它页面。

表单输入框保持统一最小宽度；数值框隐藏默认上下箭头按钮，避免长小数、单位后缀被挤压截断。

维护页视觉层级按生产维护场景重新区分：

- 顶部主标题使用最大字号和最高字重，用于明确当前页面用途。
- 标签页文字加大并加粗，保证 `通信`、`视频/相机`、`云台`、`车辆标定` 等一级分组更容易识别。
- 页内标题、页内说明、字段名称、字段说明采用不同字号、字重和颜色，避免所有文字挤在一起难以扫描。
- 底部状态栏和生产维护只读值使用独立样式，区分“当前状态信息”和“可编辑配置项”。
- 带单位的数值参数不再把单位混在可编辑文本中，而是在输入框最右侧使用独立单位标识，例如 `ms`、`m`、`deg`、`m/s`。这样编辑数值时只处理纯数字，排布也更统一。
- 参数输入控件使用点击获得焦点策略，禁止通过键盘 Tab 或页面滚动过程误选中输入框。鼠标滚轮经过输入控件时会滚动外层页面，不会改变数值。

维护页已为每个参数增加用户说明：

- 每个配置项下方显示一行浅色说明，解释该参数的含义、作用和典型调整场景。
- 鼠标悬停在标签或输入控件上也会显示同一说明，方便现场人员快速确认。
- 说明文本集中维护在 `maintenance.cpp` 的参数说明表中，后续新增配置项时应同步补充说明，避免维护人员看到“只有参数名、没有用途”的配置页。
- 生产维护页的只读状态项同样有说明，用于解释当前配置文件、运行目录、备份目录和备份数量代表什么。

维护页已加入基础校验：

- 通信 HTTP/WebSocket 地址必须是合法 URL。
- 视频预览流和相机控制基地址允许为空；为空表示禁用对应远程能力。
- 启用云台控制时 PLC 地址不能为空。
- 启用作业服务时作业服务地址必须是合法 URL。
- 视频流选项必须是 JSON 数组。
- 重连间隔、请求超时、控制周期和安全停止超时都有上下限，避免设置到明显不安全或无效范围。
- 保存前会检查退避上限、重连上限、云台软限位和车辆标定参数，阻止明显错误配置写入。

### 2.3 生产维护能力

生产维护页当前提供只读运行状态和快捷入口：

- 当前配置文件路径
- 配置是否来自文件
- 程序运行目录
- 配置备份目录
- 当前备份数量
- 最近一次备份文件
- 刷新状态
- 打开配置目录
- 打开备份目录
- 配置自检

该页用于现场维护人员确认“当前程序到底读的是哪个配置文件”，避免修改了错误目录下的 `config.json`。

### 2.4 热加载范围

当前 `保存并应用` 后可热加载：

- 首页状态轮询地址、轮询间隔、请求超时、失败退避上限、认证 token
- 底盘 WebSocket 地址、认证 token、自动重连开关、重连基础间隔、重连最大间隔
- 视频预览流、视频流选项、OAK 设备 ID、重连间隔、自动预览配置
- 工控机相机控制基地址和相机 HTTP 请求超时
- 云台 PLC 地址、端口、Unit ID、寄存器地址、轮询间隔、软限位、安全停止超时
- 路径跟踪控制参数、路径跟踪更新周期、手动控制连发周期
- 地图基准经纬度
- 直线/多垄作业服务地址、状态轮询间隔、命令超时、自动刷新开关

首页热加载时会统一重新应用以下模块配置：

- `StatusClient`：重新配置状态读取 URL、轮询间隔、请求超时、失败退避上限和认证 token。
- `ChassisClient`：断开旧 WebSocket 后按新地址、重连策略和认证 token 重连。
- `AbstractVideoSource`：按视频后端重建或复用视频源，重新设置预览流、重连间隔和自动预览。
- `CameraControlClient`：重新设置工控机相机控制基地址和请求超时；地址清空或无效时会停用远程相机控制，避免旧地址继续生效。
- `GimbalControlClient`：停止旧轮询后按新 PLC 参数重新配置并按启用状态启动轮询；云台安全停止超时会立即用于后续点动。
- `RouteFollower`：重新加载路径跟踪控制参数和更新周期。
- 首页手动控制：重新应用长按速度指令连发周期。

地图页热加载时会统一重新应用：

- 地图基准经纬度。
- 直线/多垄作业服务地址、token、轮询间隔、命令超时、自动刷新开关。
- 作业服务禁用时停止状态轮询。

## 3. 热加载边界

以下配置虽然可以保存，但热加载效果需要注意：

- `video.backend` 从 `mjpeg_http` 切到 `oak_depthai` 时，会重建视频源；如果本机没有启用 OAK 编译选项或缺少依赖，仍需按 OAK 方案处理。
- 地图基准经纬度热加载后，只影响之后的坐标换算；已经画在地图上的点不会自动重投影。
- 路径跟踪参数会立即下发到 `RouteFollower`，但正在执行的任务仍建议先暂停或停止后再应用大幅参数调整。
- 云台寄存器地址和软限位会立即应用；修改前应确认设备处于安全状态。
- 车辆标定参数当前主要用于配置留档和后续扩展，保存后会写入配置，但不是所有运行模块都会立即消费这些参数。
- 视频 `recordMode` 当前仅支持 `host_opencv`，维护页保留该字段是为了生产配置完整性和后续扩展。

## 4. 配置备份、恢复与加载

### 4.1 启动备份

程序每次启动或重启时，会在加载当前 `config.json` 后自动创建一次配置备份。

备份规则：

- 备份目录为当前配置文件同级目录下的 `config_backups`。
- 备份文件名格式为 `config_yyyyMMdd_HHmmss_zzz.json`。
- 最多保留 10 个备份文件，超过后自动删除最旧备份。
- 备份失败只记录日志和提示，不阻塞主程序启动。

### 4.2 恢复上次配置

`恢复上次配置` 会读取最近一次启动备份，并将该备份原子覆盖到当前 `config.json`，随后立即触发热加载。

按钮启用规则：

- 无备份文件时不可点击。
- 页面无任何修改且当前 `config.json` 与最近备份一致时不可点击。
- 页面存在未保存修改时可点击，用于直接放弃当前表单修改并恢复最近备份。
- 当前 `config.json` 与最近备份不一致时，即使表单未修改也可点击，用于回滚已保存配置。

### 4.3 加载配置文件

`加载配置文件` 用于从备份目录或其它位置选择一个 `.json` 配置文件，并只把该文件内容读入维护页表单。

加载规则：

- 加载后不会直接写入 `config.json`。
- 加载后不会触发运行模块热加载。
- 如果加载内容与当前运行配置不同，页面会进入“有未保存修改”状态。
- 后续点击 `保存` 时，才写入 `config.json` 但不影响当前运行模块。
- 后续点击 `保存并应用` 时，才写入 `config.json` 并热加载运行模块。

### 4.4 未保存修改拦截

维护页会跟踪表单内容是否相对当前运行配置发生变化。

状态规则：

- 未修改时，`保存`、`保存并应用` 不可点击。
- 修改任意参数后，`保存`、`保存并应用` 可点击。
- 修改任意参数后，若存在备份，`恢复上次配置` 可点击。

当维护页存在未保存修改，并通过顶部菜单切换到首页、地图、帮助、关于页面，或直接关闭退出程序时，会弹窗提示 `是否保存本次修改`。

弹窗选项：

- `取消`：不保存当前任何参数修改，重新加载当前运行配置后继续切换页面。
- `保存`：写入 `config.json`，不热加载，保存成功后继续切换页面。
- `保存并应用`：写入 `config.json` 并热加载，成功后继续切换页面。

## 5. 使用流程

1. 打开 `维护` 页面。
2. 在对应标签页修改配置。
3. 点击 `保存`，只写入配置文件。
4. 点击 `保存并应用`，写入配置文件并热加载运行中模块。
5. 点击 `还原运行配置`，放弃当前表单未保存编辑，并重新显示当前内存中的运行配置。
6. 点击 `恢复上次配置`，将最近一次启动备份恢复到当前配置文件并立即应用。
7. 点击 `加载配置文件`，选择一个 `.json` 文件读入表单；确认无误后再选择 `保存` 或 `保存并应用`。
8. 打开 `生产维护` 页，确认当前配置文件、备份目录和最近备份是否符合预期。
9. 点击 `配置自检`，确认当前表单没有明显格式、范围或路径问题。
10. 如修改通信地址，观察首页日志和地图作业状态是否显示重新连接/重新配置结果。

## 6. 验收项

- 修改底盘 WebSocket 地址后点击 `保存并应用`，首页 WebSocket 会按新地址重新连接。
- 修改状态读取 URL 后点击 `保存并应用`，首页状态轮询使用新地址。
- 修改视频流 URL 后点击 `保存并应用`，首页视频区使用新流地址。
- 清空相机控制基地址后点击 `保存并应用`，首页拍照/录像不再调用工控机相机 HTTP 控制接口。
- 修改云台 PLC 地址或软限位后点击 `保存并应用`，云台控制使用新配置。
- 修改云台安全停止超时后点击 `保存并应用`，后续俯仰/水平点动使用新超时。
- 修改底盘重连间隔或自动重连开关后点击 `保存并应用`，底盘 WebSocket 使用新重连策略。
- 修改状态请求超时和失败退避上限后点击 `保存并应用`，状态轮询使用新网络策略。
- 修改相机控制请求超时后点击 `保存并应用`，拍照、录像和状态查询使用新超时。
- 修改路径跟踪更新周期或手动速度连发周期后点击 `保存并应用`，路径执行和首页手动控制使用新周期。
- 修改作业服务地址后点击 `保存并应用`，地图页作业服务使用新地址。
- 点击 `保存` 后，配置文件改变，但当前运行中连接不变。
- 输入非法 URL 或非法视频流 JSON 时，维护页应阻止保存并给出提示。
- 程序启动后，`config_backups` 目录自动生成一份启动配置备份，且最多保留 10 个。
- 页面未修改且当前配置与最近备份一致时，`保存`、`保存并应用`、`恢复上次配置` 不可点击。
- 修改任意参数后，`保存`、`保存并应用` 可点击；存在备份时 `恢复上次配置` 可点击。
- 点击 `加载配置文件` 后，所选配置只进入表单，不立即写盘或热加载。
- 维护页有未保存修改时切换顶部菜单，会弹出 `是否保存本次修改`。
- 维护页有未保存修改时直接关闭程序，会弹出 `是否保存本次修改`。
- 在维护页滚动配置列表时，鼠标滚轮不会直接改变数值输入框内的参数。
- `生产维护` 页能显示当前配置文件、运行目录、备份目录、备份数量和最近备份。
- `生产维护` 页可以打开配置目录和备份目录。
- `生产维护` 页可以执行配置自检，发现 URL、软限位、标定值、重连间隔等明显问题。
