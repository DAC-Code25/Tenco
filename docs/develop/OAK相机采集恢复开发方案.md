## 实施设计

- 采集失败或连续无合法新帧时清除缓存、停止当前录像、记录时间/失败原因，释放旧队列/设备并按 1～10 秒有界退避重新建立 pipeline。收到首个合法新帧才报告连接成功；帧新鲜度用单调时钟，状态保留最近错误/重连次数/帧序号与年龄。录像故障后不自动重开。
- 把 DepthAI 读帧适配与恢复状态分开，以同一生产恢复循环注入假采集源验证断连、重连、卡帧、缓存失效和停止；测试不用真实设备、不切换运行服务。
- 所有设备/队列在采集线程创建与释放；HTTP/录像共享状态明确加锁，停止可打断退避。客户端只获取合法且新鲜的 JPEG，断开/恢复期间不会返回旧缓存；未采集到帧返回 HTTP 503，可保留原 JSON 字段兼容并追加诊断字段。
- HTTP 连接数量有界，recv/send 有限等待；退出先停止接收/中断客户连接并回收线程，再销毁 camera，避免原 detach 引用已析构对象。HTTP/状态 API 路径及照片/录像行为兼容。
- CLI 参数严格检查，增加帧新鲜度/无帧重建/重连间隔配置；保持现有默认画质与低延迟配置。保留错误信息并写日志，不通过延长 Qt 超时掩盖相机失败。
