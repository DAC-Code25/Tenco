## 本次实施补充（2026-09-15）

### 基线、范围与验收

本次按工作空间 v2.0 方案完整实施软件部分。完整方案快照见同目录的《工控机闭环系统总体方案V2.md》。开发前两个仓库磁盘工作区、暂存区干净，已 fetch/prune 并快进核对远端主分支。手动控制仍直接与底盘通信，Tenco 删除 RouteFollower 和旧 row-work 客户端。不开启 WSL，不引入 Windows ROS。

### 实施选择及修改范围

采用同一份可移植 C++17 控制核心，Windows 直接运行几何、PP、速度、状态机、协议及闭环仿真测试；ROS 节点只适配消息和设备。新增 control_common 共享包，提供纯位姿数据、坐标/标定、JSON、HTTP、采样与存储基础设施，避免 sensor_fusion 与 tracking_node 循环依赖。JSON 使用 jsoncpp，YAML 使用 yaml-cpp，HTTP/WS 使用 Boost.Beast/Asio。拒绝第二份 Windows 跟踪算法、旧自动回退和空壳模块。

工控机新增 ControlPoseBuilder、源采纳健康导出、PoseService、tracking_node、配置/迁移/部署脚本和 Linux CI；删除 network_sender 及专用配置。Tenco 新增共享客户端、控制协调器、任务编译及坐标适配，修改 Map/Home/配置维护/遥测/文档，删除旧执行链。所有设备地址、版本、限制从配置加载。

### 外部条件和协议决策

11F1E2 手册确认支持 Jetson Orin NX/Nano（ARM64），未确认实机模组、系统及 ROS 版本。源脚本使用 Humble，Linux CI 以 Ubuntu 22.04 / Humble 为构建基线；最终 ARM64 构建和部署必须核实目标机环境。底盘固件源码不在工作区，不能伪造其支持代次、TTL 或急停。为服务、客户端和模拟底盘定义版本化的 tenco-control-v1 适配契约，能力文件默认未验证；生产自动运动必须同时通过标定、场地、定位策略和底盘能力验证。手动直连报文保持原格式，启用双通道后必须有底盘权属确认。

### 性能、并发、可靠性与兼容性

控制线程独占执行状态，使用 steady_clock 的真实 dt；网络、几何预处理与文件落盘不阻塞控制循环。队列、请求体、长轮询、事件与历史结果有界；停止优先，重复请求按内容去重，运动许可短时有效。共享不可变快照，异步回调保留对象生命周期，退出先停止/释放、再取消网络并 join。失败关闭自动许可，重连/重启/复位不自动运动。地图和配置提供版本迁移及备份，未知坐标拒绝任务。视频、日志、数据库、PLC 仅做必要接线，保持既有功能。

### 测试与阶段

1. 固化跨端协议、共享数据、标定/原点和安全配置。
2. 实现控制核心，验证几何、左右纠偏、真实距离终点、速度/轮速限制、转向、所有任务原语及闭环故障场景。
3. 实现 fusion 同快照 ROS/HTTP、采样、真实观测年龄；保留 UKF/EKF 更新公式。
4. 实现跟踪服务、所有权、幂等/许可、事件/结果、原点和存储，以及模拟底盘和 Linux 集成测试。
5. 实现 Tenco 全任务编译/客户端/协调接线并删除旧代码，迁移配置/地图、更新帮助。
6. 当前工作副本使用固定 Qt 6.5.3 / MinGW 11.2 / Ninja / Debug 完整构建和 CTest，执行 GUI 冒烟；Linux CI 使用 colcon 构建和测试全部 ROS 包。
7. 逐项对照总体方案、记录实际结果；两个分支分别中文提交、推送、创建 PR。尚缺现场设备的验收项保留为未完成，不将仿真精度冒充实车精度。

### 风险和回退

跨进程控制权与实际制动必须现场验证；未知能力禁止自动上线。回退按两个仓库的基线提交成套切换，先停稳/撤销许可，再切换发布版本；不保留运行时旧控制器。地图/配置迁移保留备份，不能混用新旧原点。遇到实现范围变化先更新本方案和记录。
