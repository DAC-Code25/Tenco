## 坐标与定位准入

融合服务的 `map` 是 ENU：x 向东、y 向北，位置用米；yaw 用弧度，从东向北逆时针，参考点为 base_link。融合参考点偏移和旋转在发布端应用一次，速度使用同一参考点。Qt 保留地图模型南/东轴，MapFrameAdapter 统一正反转换，最后再变为场景像素；视图旋转不进入上传坐标。

四个方向车头、五个方向单垄箭头、负坐标、非零旋转/平移、非零参考点、规划返回 ENU 均有独立数值断言。动态跨仓样例中模型和图形坐标误差约 1e-15 m，仅表示浮点计算一致，不能作为实车厘米级精度证据。

以下样例直接检查真实 Map 页面中的 QGraphicsItem 和 TaskCompiler 输出，预期值独立给定：

| 场景 | 输入与预期结果 |
|---|---|
| 无地图旋转/平移 | ENU `(-3, 2)` m → 地图模型 `(-2, -3)` m → 默认 50 px/m 场景 `(-150, -100)` px；车辆和示教点落在同一位置 |
| 车头朝向 | ENU yaw `0、π/2、π、-π/2` → 默认视图中的右、上、左、下；同时核对车辆及地图点箭头 |
| 非零坐标绑定 | 绑定平移 `(10, -4)` m、旋转 `π/2`；ENU `(8, -7)` m → 模型 `(-2, -3)` m → 相同场景位置 |
| 规划正向变换 | 上述绑定下，地图路线 `(-2, -3) → (-2, -1)` m 上传为 ENU `(8, -7) → (8, -5)` m |
| 展示独立性 | 视图再旋转 90°，上传的路径点和任务规划版本不变；新增实际地图点则使规划版本变化 |
| 小位移与失效数据 | 5 mm / 3 mm 位移立即进入实际图形；失效位姿不覆盖最后已知位置，该位置暗显且不作为当前可用位姿 |

在实际场地，上述一致性还要求使用正确的 GNSS 原点、地图绑定和车辆参考点标定；这些现场参数需要单独验收。

`validForControl` 保留有限值、已初始化、确认的坐标/标定、新鲜融合状态和编码器反馈、时间未倒退等基础检查。RTK 非 FIX、低星、可靠性标志为 false 或原始观测短缺不单独禁止行驶；降级时按减速度限制平滑减至 0.10 m/s，质量恢复后平滑恢复任务速度。状态和反馈窗口统一 350 ms，硬失联 1000 ms。未经实际初始化/标定或真正失去状态流，不会凭一个格式合法的 JSON 放行。

两个链路使用实际生产组件并检查公共位姿/任务接口。Windows Qt 与 Linux ROS 验证分环境进行，没有声称在 Windows 原生运行 ROS，也没有用直接注入融合输出的仿真代替生产 UKF 验证。
