# Tenco 上位机

Qt 6 Widgets/C++20 上位机，负责设备状态、独立手动控制、地图/示教/规划、整项任务下发与监视，以及工控机相机预览/拍摄。自动跟踪由工控机执行；相机服务源码在并列的 [oak-camera-service](https://github.com/DAC-Code25/oak-camera-service) 仓库。

完整工作空间的唯一约束为 [根 AGENTS.md](../AGENTS.md)，架构、最近确认的状态和待办集中在 [项目说明](../docs/项目总览.md)。本仓库 README 只说明使用方法。

## 本地构建与运行

固定本机 Kit 为 Qt 6.5.3/MinGW 11.2，CMake/Ninja，Debug，`BUILD_TESTING=ON`、`TENCO_BUILD_TESTS=ON`、`-DQT_QML_DEBUG`。工作空间构建目录为 `Tenco/build/ipc-task-client-v1-Qt6.5.3-Debug`，完整配置、构建和 CTest 命令见根总约束。

Qt Creator 打开当前仓库 `CMakeLists.txt`，选择 Desktop Qt 6.5.3 MinGW 64-bit 和上述构建目录。不要复用另一个源码副本的缓存。依赖 Core、Gui、Widgets、Network、WebSockets、Sql；关于页按可用性加载 Quick/QuickWidgets/Quick3D/Quick3DAssetUtils。程序输出到工作空间 `bin/`。Windows 构建默认使用所选 Qt Kit 的 `windeployqt` 将 Qt DLL、QML/平台/SQLite 插件和编译器运行库部署到程序旁，桌面快捷方式可直接指向 `bin/Tenco.exe`，无需开发环境 PATH；隔离构建可显式关闭 `TENCO_DEPLOY_WINDOWS_RUNTIME`。

已正确配置 Qt/编译器环境时，也可在仓库根使用预设进行补充验证：

```powershell
cmake --preset default
cmake --build --preset default
ctest --preset default
```

发布打包在用户明确要求时使用 release 预设及 `scripts/package_windows.ps1`。本地修改默认不提交、不推送、不创建或合并 PR，不要求 CI。

启动可显式指定配置：

```powershell
..\bin\Tenco.exe --config ..\bin\config.json
```

## 配置

未传 `--config` 时固定使用可执行文件目录的 `config.json`，不随启动器当前目录改变；`--config` 仅作显式运行/测试覆盖。实际路径可由 ConfigManager::configFilePath 查询。`bin/config.json` 是运行配置；构建和安装仅在目标配置缺失时从源码模板初始化，已有配置逐字节保留，避免清空认证令牌或覆盖现场地址。

维护导航分为“状态总览”“工控机 · 服务与参数”“本机 · 连接与手动”“本机 · 相机与云台”“本机 · 备份与日志”，各组内按功能分页。三项服务、融合/导航参数和相机采集参数在工控机页操作并回读；本机页底部的保存/应用只管理上位机 `config.json`、连接与偏好。自动任务速度、转向速度及到达容差只在工控机导航参数中修改，常规任务和直线任务统一使用导航服务当前生效配置，不再读取本机或地图中的旧控制参数。原点和标定只读详情归工控机页，融合启动/重启/参数应用前统一确认本次基准坐标。参数说明以悬停提示或详情展示；鼠标滚轮用于浏览页面，不改变数值框或收起的下拉框参数，编辑时使用键盘、步进按钮或展开选项。

启动、保存和恢复前，原字节快照与 SHA-256 清单统一放在 `<appDir>/backups/config/local`。相同内容复用已验证快照，不自动删除现场备份；旧 `<appDir>/config_backups` 可读兼容，不盲目迁移。可手动备份、打开目录和选择恢复；恢复校验版本与摘要，先备份当前文件再覆盖。备份失败、磁盘被其他进程改写、损坏或不支持的 schema 都会拒绝覆盖。导入仅预览且提示可能覆盖连接凭据，未知字段在保存时保留；磁盘版本与当前运行版本分别展示。

| 配置组 | 用途 |
|---|---|
| `manualControl` | 独立手动速度上限、发送心跳 |
| `poseSource`、`tracking` | 工控机服务地址（包含 `/api/v1`）、超时及使能 |
| `routePlanning` | 最短路 minEdgeCost、edgePenalty、arcPenalty |
| `network` | 底盘 websocketUrl、statusReadUrl、认证和状态轮询 |
| `video` | 工控机相机服务 controlBaseUrl、通用 MJPEG 兼容地址 streamUrl、后端及本地显示/重连参数 |
| `gimbal` | PLC 连接、状态及软限位 |
| `logging` | 日志等级、轮转、脱敏、审计和导出 |
| `database` | SQLite 或 PostgreSQL 连接、WAL、外键及缓存选项 |

schemaVersion=2；旧 schema1 的 control 仅兼容独立手动通道设置。历史 `geo/taskDefaults/control/rowWork` 中的原点及自动控制值不再参与运行；启动不改写原文件，显式保存、导入保存或恢复时保留原字节备份，再清除退役字段，不会将它们写入工控机。未知版本禁止默认值覆盖。车辆、融合及导航参数由工控机统一管理；上位机缺少有效导航参数时明确提示读取/更新工控机服务，不使用另一套本机默认值生成任务。

`TENCO_AUTH_TOKEN` 和 `TENCO_DATABASE_PASSWORD` 可覆盖相应敏感配置。SQLite 默认 `<appDir>/data/tenco.sqlite3`；PostgreSQL/TimescaleDB 扩展不能称为已经完成的全套中心化系统。

`network.*` 指向底盘，`video.controlBaseUrl` 是工控机相机服务的唯一地址，统一用于彩色预览、深度预览、拍照、录像和状态查询。配置有效服务地址后，两路预览分别使用该服务的 `/camera/stream.mjpeg` 和 `/camera/depth/stream.mjpeg`，旧 streamUrl 不覆盖其中任何一路；只有未配置服务地址时才显示并使用通用 MJPEG 兼容地址。生产预览用 `mjpeg_http`，本机 OAK 调试可用 `oak_depthai`，本机后端隐藏远端地址。首页只提供“彩色 / 深度”预览选择和“开启 / 关闭预览”按钮；关闭预览时选择来源不会自动开流。本机 OAK 后端不提供深度预览。

配置了 controlBaseUrl 时，拍照/录像调用工控机接口，媒体留在工控机 Capture；切换或关闭深度预览不改变 RGB 照片、RGB 录像及任务拍照行为，服务端媒体目录不由首页按钮另行修改。本地视频录像后端另行配置，不能把历史拼接 MJPEG 文件当作远端 MP4。“工控机 · 服务与参数”的相机采集区提供显式读取/应用服务端尺寸和 FPS，并回读真实生效状态；本机连接设置位于“本机 · 相机与云台”，本机保存不覆盖工控机采集设置。

## 操作与接口

相机已接通但无画面时，先在“本机 · 相机与云台”核对工控机相机服务地址是否为当前有线或无线地址，并检查首页预览是否开启。预览连续 5 秒无数据会报错并重连；这是接收空闲超时，持续有数据的视频流不受播放总时长限制。

自动任务：地图/示教 → 规划完整任务 → “下发并执行” → 工控机自主执行。主操作自动完成上传、匹配任务的 Ready 确认和一次明确启动。重开遇到 Ready/Paused 任务时，先点击“启动任务”/“继续任务”回读真实计划、校核版本并预览确认；此次确认不运动，确认完成后须再次明确点击才启动或继续。普通自动任务不依赖上位机在线，检查点拍照确认仍由上位机业务协调。

首页的定位状态、自动任务状态和“本段进度”为只读概览，不提供手动/自动模式切换；任务启动、暂停、继续和结束统一在地图页“任务执行”区操作。“本段进度”表示当前路径段，进入下一段后重新计算，不代表整项任务的总完成率。概览区分新鲜反馈、状态延迟和离线；延迟时保留的内容属于上次数据，不能据此认定当前位置、任务进展或已经停稳。底盘电池与数字速度继续独立显示，不替代融合定位和导航反馈。

地图页只保留“常规任务”和“直线任务”：前者按地图点与路径关系组合路线，后者通过 A/B 作业线、检查点及往返设置规划。直线任务下发后，工控机按启动时的实时位置先沿原线回到起点 A，停稳后开始正式作业；已在 A 容差内则停稳后直接开始。回起点途中不触发检查点停留或拍照，循环不重复该准备阶段；超出原路径允许范围时拒绝启动。两者共用固定的“任务执行”区域，集中显示执行状态、进度及操作结果，并提供暂停、继续、结束等控制；不再设置多垄任务编辑或执行入口。旧地图内的多垄数据仅作为原始业务内容保留，不参与当前任务规划。

两类任务共用工控机跟踪控制和当前生效的导航参数，区别在任务编排，并非两套精度模式。常规任务适合多点巡航，例如 `1→2→…→12→1`；每段按已有路径关系规划，若要返回或循环，必须明确编排回起点的路线。直线任务适合沿同一条示教作业线往返，检查点可分别选择去程/返程停留和拍照；已记录的中间点保留实际坐标，并不强制拉成数学直线，也不适合替代任意大转角的巡航路线。任务拍照仍需上位机协调确认。

需要人工确认未知的检查点拍摄结果时，“任务执行”区才显示“核对拍摄结果”。核对绑定当前事件，不重新拍摄，不覆盖已有成功/失败结果；取消保留等待，人工暂停仍需明确继续。

左侧编辑区按“点位”“路径”“地图”分页；常用点位与批量生成放在同页，路径关系和网格显示单独管理。“地图”页的“坐标适配…”核对地图绑定及坐标变换，不修改全局基站坐标；新空白地图自动绑定当前有效原点，旧地图不会静默改绑。编辑模式下“记录车辆点”将当前车位移至视图中心，并按序新增含当前有效位置和朝向的地图点；关闭编辑或任务进行中显示“定位车辆”，仅居中。实时位姿持续更新车辆显示，不会替换用户已选择的路线起点。默认地图目录固定为程序旁的 `maps/`，本机为 `bin/maps/`；加载及另存默认从该目录打开，新地图建议名为 `yyyy-MM-dd.json`，同日已有文件则依次使用 `-2`、`-3` 后缀。新建不提前写盘，快速保存继续写入当前已选地图文件。

添加两点间的直线或圆弧关系时，可选择“单向”或“双向”，新建关系默认双向。双向关系只保存一份几何，反向规划沿同一几何反序行驶，无需再建一条反向关系。地图文件使用 schema 3；旧 schema 1/2 保持原单向含义，不会自动变成双向，也不改变原地图坐标绑定。此版本号与本机配置的 schemaVersion 无关。

无线监视与工控机本地控制分别判断：上位机状态超过 1 秒标记为延迟，5 秒内保留带提示的上次状态；显式任务操作最多使用 3 秒内的快照，并由工控机核对状态版本、短期操作许可和本地实时传感器。超过时限不能启动或继续，断线重连不重发运动请求，结果不明只按请求 ID 查询。请求超时缺省为 5 秒，已有显式超时配置继续保留；会话和操作许可采用服务端给出的有效期并扣除往返耗时。本机位姿显示仍按真实年龄判断，过期位置不会继续当作实时车位显示。

暂停/结束使用独立的停止请求连接，监视延迟、操作会话过期及其他写操作不会阻挡已知执行身份的停止请求；工控机仍校验启动身份、任务及执行 ID，未知身份不能停止另一项任务。急停独立于普通操作。停止结果分为未发送、等待确认、已受理/应用及实测停稳，只有工控机反馈新鲜有效并持续停稳后才显示停稳；结果未知只查询，不排队重发。无线延迟时首页原点与维护配置保留并标注为上次数据，不冒称运行状态已确认。

手动：按钮长按或 W/A/S/D → 原 WebSocket cmd_vel；松键发送本通道零速，断线清输入、重连不重放。首页的速度设置只作用于独立手动控制；“手动停止”清除手动输入并停止云台，自动任务使用地图页任务执行区的暂停、结束或急停。首页保持电池图标与数字速度显示，底盘反馈离线时保留原显示并标注状态延迟，不能据此判断车辆已停稳。PLC 云台为另一条 Modbus 链路，UI 应答成功不等于机械运动已经确认。

## 排查

测试进程以 `0xc0000135` 退出时，先将 Qt 和 MinGW bin 加入 PATH。状态日志 http=0、Operation canceled、device not open 时，检查 statusReadUrl、设备在线和超时；当前请求有超时及失败退避。WebSocket 代理异常时检查系统代理，ChassisClient 已使用 NoProxy。

`ping` 通只说明网络可达。工控机维护接口为 `18133`，返回 `401` 时应核对运行配置的 `network.authToken` 是否与工控机一致；导航 `18130`、融合 `18131` 随各自服务启动，服务停止时端口不监听。首页“底盘在线/状态延迟”对应底盘 HTTP 状态监视，不能据此认定工控机断网；远程启动仍按先融合、后导航进行。

视频异常先检查相机服务地址、实际预览接口的 multipart/x-mixed-replace 和相机 status 的帧新鲜度；通用 MJPEG 模式再核对 streamUrl。HTTP 可达不能证明采集健康。Windows 风格与自定义 QSS 导致 SpinBox 步进显示错位时可用 `-style fusion` 核对。

GUI 冒烟入口仅测试构建启用，使用回环配置并关闭真实设备服务。云台间歇失效、拍摄恢复偶发失败和现场验收缺口集中保留在项目说明；本地/仿真通过不等于实车通过。
