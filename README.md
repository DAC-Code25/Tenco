# Tenco 上位机

Qt 6 Widgets/C++20 上位机，负责设备状态、独立手动控制、地图/示教/规划、整项任务下发与监视，以及工控机相机预览/拍摄。自动跟踪由工控机执行；相机服务源码在并列的 [oak-camera-service](https://github.com/DAC-Code25/oak-camera-service) 仓库。

完整工作空间的唯一约束为 [根 AGENTS.md](../AGENTS.md)，系统架构见 [系统说明](../README.md)，整体验证和待办见 [系统记录](../docs/项目总览.md)。本页集中说明上位机功能、操作、接口和构建，实质变更见 [CHANGELOG](CHANGELOG.md)。

## 本地构建与运行

固定本机 Kit 为 Qt 6.5.3/MinGW 11.2，CMake/Ninja，Debug，`BUILD_TESTING=ON`、`TENCO_BUILD_TESTS=ON`、`-DQT_QML_DEBUG`。工作空间构建目录为 `Tenco/build/ipc-task-client-v1-Qt6.5.3-Debug`，完整配置、构建和 CTest 命令见根总约束。

Qt Creator 打开当前仓库 `CMakeLists.txt`，选择 Desktop Qt 6.5.3 MinGW 64-bit 和上述构建目录。不要复用另一个源码副本的缓存。依赖 Core、Gui、Widgets、Network、WebSockets、Sql；关于页按可用性加载 Quick/QuickWidgets/Quick3D/Quick3DAssetUtils。程序输出到工作空间 `bin/`。Windows 构建默认使用所选 Qt Kit 的 `windeployqt` 将 Qt DLL、QML/平台/SQLite 插件和编译器运行库部署到程序旁，桌面快捷方式可直接指向 `bin/Tenco.exe`，无需开发环境 PATH；隔离构建可显式关闭 `TENCO_DEPLOY_WINDOWS_RUNTIME`。

已正确配置 Qt/编译器环境时，也可在仓库根使用预设进行补充验证：

```powershell
cmake --preset default
cmake --build --preset default
ctest --preset default
```

发布打包在用户明确要求时使用 release 预设及 `scripts/package_windows.ps1`。本地修改默认不提交、不推送、不创建或合并 PR，不要求 CI。

启动可显式指定配置：

```powershell
..\bin\Tenco.exe --config ..\bin\config.json
```

## 配置

未传 `--config` 时固定使用可执行文件目录的 `config.json`，不随启动器当前目录改变；`--config` 仅作显式运行/测试覆盖。实际路径可由 ConfigManager::configFilePath 查询。`bin/config.json` 是运行配置；构建和安装仅在目标配置缺失时从源码模板初始化，已有配置逐字节保留，避免清空认证令牌或覆盖现场地址。

维护导航分为“状态总览”“工控机 · 服务与参数”“本机 · 连接与手动”“本机 · 相机与云台”“本机 · 备份与日志”，各组内按功能分页。三项服务、融合/导航参数和相机采集参数在工控机页操作并回读；本机页底部的保存/应用只管理上位机 `config.json`、连接与偏好。自动任务速度、转向速度及到达容差只在工控机导航参数中修改，常规任务和直线任务统一使用导航服务当前生效配置，不再读取本机或地图中的旧控制参数。原点和标定只读详情归工控机页，融合启动/重启/参数应用前统一确认本次基准坐标。参数说明以悬停提示或详情展示；鼠标滚轮用于浏览页面，不改变数值框或收起的下拉框参数，编辑时使用键盘、步进按钮或展开选项。

启动、保存和恢复前，原字节快照与 SHA-256 清单统一放在 `<appDir>/backups/config/local`。相同内容复用已验证快照，不自动删除现场备份；旧 `<appDir>/config_backups` 可读兼容，不盲目迁移。可手动备份、打开目录和选择恢复；恢复校验版本与摘要，先备份当前文件再覆盖。备份失败、磁盘被其他进程改写、损坏或不支持的 schema 都会拒绝覆盖。导入仅预览且提示可能覆盖连接凭据，未知字段在保存时保留；磁盘版本与当前运行版本分别展示。

| 配置组 | 用途 |
|---|---|
| `manualControl` | 独立手动速度上限、发送心跳 |
| `poseSource`、`tracking` | 工控机服务地址（包含 `/api/v1`）、超时及使能 |
| `routePlanning` | 最短路 minEdgeCost、edgePenalty、arcPenalty |
| `network` | 底盘 websocketUrl、statusReadUrl、认证和状态轮询 |
| `video` | 工控机相机服务 controlBaseUrl、通用 MJPEG 兼容地址 streamUrl、后端及本地显示/重连参数 |
| `gimbal` | PLC 连接、状态及软限位 |
| `logging` | 日志等级、轮转、脱敏、审计和导出 |
| `database` | SQLite 或 PostgreSQL 连接、WAL、外键及缓存选项 |

schemaVersion=2；旧 schema1 的 control 仅兼容独立手动通道设置。历史 `geo/taskDefaults/control/rowWork` 中的原点及自动控制值不再参与运行；启动不改写原文件，显式保存、导入保存或恢复时保留原字节备份，再清除退役字段，不会将它们写入工控机。未知版本禁止默认值覆盖。车辆、融合及导航参数由工控机统一管理；上位机缺少有效导航参数时明确提示读取/更新工控机服务，不使用另一套本机默认值生成任务。

`TENCO_AUTH_TOKEN` 和 `TENCO_DATABASE_PASSWORD` 可覆盖相应敏感配置。SQLite 默认 `<appDir>/data/tenco.sqlite3`；PostgreSQL/TimescaleDB 扩展不能称为已经完成的全套中心化系统。

`network.*` 指向底盘，`video.controlBaseUrl` 是工控机相机服务的唯一地址，统一用于彩色预览、深度预览、拍照、录像和状态查询。配置有效服务地址后，两路预览分别使用该服务的 `/camera/stream.mjpeg` 和 `/camera/depth/stream.mjpeg`，旧 streamUrl 不覆盖其中任何一路；只有未配置服务地址时才显示并使用通用 MJPEG 兼容地址。生产预览用 `mjpeg_http`，本机 OAK 调试可用 `oak_depthai`，本机后端隐藏远端地址。首页只提供“彩色 / 深度”预览选择和“开启 / 关闭预览”按钮；关闭预览时选择来源不会自动开流。本机 OAK 后端不提供深度预览。

配置了 controlBaseUrl 时，拍照/录像调用工控机接口，媒体留在工控机 Capture；切换或关闭深度预览不改变 RGB 照片、RGB 录像及任务拍照行为，服务端媒体目录不由首页按钮另行修改。本地视频录像后端另行配置，不能把历史拼接 MJPEG 文件当作远端 MP4。“工控机 · 服务与参数”的相机采集区提供显式读取/应用服务端尺寸和 FPS，并回读真实生效状态；本机连接设置位于“本机 · 相机与云台”，本机保存不覆盖工控机采集设置。

本模块变更和历史测量见 [CHANGELOG](CHANGELOG.md)。

## 操作、控制职责和接口

Tenco 负责地图编辑、寻路、整项任务编译、静止示教、任务下发和监视。常规任务和直线任务均编译为 follow_path / turn / wait 步骤，直线任务另有一次性的 return_to_start 首步，由工控机一次接收并校验。Pure Pursuit、速度规划、路径进度、停车及循环全部在 tracking_node 执行。上位机已删除 RouteFollower、RowWorkClient 和本地自动速度链路。

固定 `final_http / vehicle_footprint` 模式下，常规路线同一逻辑段内部若拆出孤立两点微段，长度严格小于本次任务到点容差、前后均为不小于容差的路径且都有计划转向，编译器省去微段前的入段转向。原路径坐标、步骤身份、独立停车及后续目标航向保留；工控机仍按实时位置、捕获范围和实测停稳决定是否直接确认到点，条件不满足时继续原对准/跟踪流程。连续微段、首末微段、严格模式及直线任务保持原编译行为。此优化在重新编译下发的任务中使用，不改写已有任务或地图。

工控机负责融合计算；当前版本已修正静止航向约束使用扣除已知零偏的陀螺值，与预测链路保持一致。独立 `fusion_pose_bridge` 接收原发送器最终 HTTP 位姿，将原发送体中已经保留三位小数的 `x/y/yaw` 按原源 50 Hz 节拍，分别转发为上位机 HTTP NDJSON 流和导航 ROS ControlPose；不重新预测、平滑、舍入或施加参考点变换。启动包装仅改变原发送器的 `network.post_url`，桥接读取并校核原融合配置，不向原算法覆写共享原点或其他参数；原点、输出坐标或轮参数不匹配时明确拒绝启动。

手动按钮和键盘仍经 MotionCommandArbiter → ChassisClient → 底盘 WebSocket。手动直接发送既有 cmd_vel，不申请许可，不调用任务服务。自动使用另一条 WebSocket 连接发送相同格式，两路独立，不增加仲裁。现有 Lua 脚本不修改。

## 2. 配置和首次使用

1. 配置 `poseSource.baseUrl=http://<工控机>:18131/api/v1`、`tracking.baseUrl=http://<工控机>:18130/api/v1`；位姿客户端会持续订阅 `/pose/stream`，服务端必须支持该推送接口。手动 `network.websocketUrl` 保持直连底盘。`network.authToken` / 环境变量 `TENCO_AUTH_TOKEN` 用于 HTTP 和手动 WS 认证。
2. 工控机的共享配置提供原点、车辆标定、定位策略和场地安全参数；本车长宽 0.80×0.30 m、轮距 0.25 m、左右轮径 0.20 m、轮端 ticks/rev=65536。自动任务速度和转向上限使用工控机 `control.max_linear_speed_mps/max_angular_speed_radps`，到达容差使用 `arrival.goal_tolerance_m/turning.angle_tolerance_rad`，只在“工控机 · 服务与参数 → 导航参数”修改。所有规划方式读取同一运行配置；旧本机及单垄文件中的速度、容差不再覆盖任务。新的配置/标定版本需重新编译上传任务，不能用旧任务绕过版本检查。最终 HTTP 位姿与驱动轮轴均在车身中心；制动保持保守估计，实际速度取工控机唯一上限与任务、场地、曲率、轮速及制动限制的较小值，不伪称已实测。车辆标定页只读显示，上位机不保存第二套融合、车辆或 PP 参数。
3. 连接 fusion、tracking 并读取当前原点和车辆配置。下发、启动、继续、复位和确认回读时自动申请操作会话，无需单独获取操作权；发送前准备最长等待 10 秒。暂停/中止使用绑定当前执行身份的独立停止通道，不等待操作会话或监视快照恢复。断线、服务重启、地图绑定或任务身份改变会取消后续启动，重连不自动重发。
4. 标准导航的全新空白地图自动绑定当前有效工控机原点，采用 ENU 零平移/零旋转；历史地图轴仍由南/东适配为东/北。已有文件、已有规划内容或旧原点地图不会静默改绑，需要新建地图，或在地图左侧“地图”页的“坐标适配…”核对绑定与变换；此操作修改地图绑定，不修改全局基站经纬度。
5. 在“常规任务”中规划路线；“直线任务”可按“记录起点 → 沿途添加中间点 → 记录终点”的顺序建图，也可在已有起终点后补点。中间点保留采集时的原始 XY，保存重开后仍以这些点构成示教折线；站距仅用于排序，记录点的站距只读。确认终点时校核站距是否位于两端之间，同站距的不同位置会拒绝，失败保留已有点。禁用检查点动作仍保留其路径形状，停留和拍照可提前设置。新几何使用 rowWork schema 3，旧版本明确拒绝；旧站距地图仍按 A–B 直线解释，并常驻提示原始 XY 缺失，需要重新采样，不能自动还原地面弯曲。已有中间点时更改起点会提示先清空中间点；执行前仍须完整有效的起终点。地图连接路径不显示箭头，绿色表示双向、橙色表示单向；常规及直线任务规划均用蓝色虚线，实时融合定位轨迹用紫色实线，重合时以分层线宽区分，定位轨迹不吸附规划线，也不代表独立地面实测。回读计划弹窗中，返回起点计划用青色点划线。标准导航自动读取工控机 `navigation_defaults` 默认通道，按固定车身尺寸处理转向，无需每项任务填写通道或转向区域 ID；请求速度和转向速度受当前工控机上限约束。旧严格配置保留显式区域校验。
6. 在“常规任务”或“直线任务”页点击一次“下发并执行”。上位机冻结本次点击时的完整计划、坐标上下文和服务/任务身份，发送一次 prepare；收到该请求的 applied 结果，并确认同一导航服务下的目标任务和版本处于 Ready 后，再发送一次 start。下发、校验及就绪的串联从本次点击起最多等待 15 秒，其中发送前准备另受 10 秒上限约束；准备或就绪失败会取消后续启动并显示原因。工控机仍检查本机有效实时位姿、实测反馈、停稳和任务版本。启动不清除手动输入，也不要求上位机手动底盘连接在线。
   直线任务会先执行一次 `return_to_start`：启动时由工控机实时位姿接入示教路径的 B→A 反向折线，沿相同几何返回 A，必要时停稳调头后正向行驶。准备路径必须与连续正式去程的完整反向一致，不允许漏弯或直连捷径；沿 A→B 主轴保持单调，急弯仍受须显式转向的限制。已在 A 到点容差内时，只确认实测连续停稳后进入正式步骤。回程不执行停留或拍照；到 A 停稳后才开始正式动作和 A→B→A 作业，后续循环跳过准备步骤。远离原路径允许范围时拒绝启动，不从任意位置直连 A。状态显示“正在返回起点”，暂停或故障仍明确显示；返回完成后的首次对准以规划 A 为锚点。两端需要同步更新才能使用新的示教折线回程。普通路线任务的起始捕获规则保持。
7. 客户端重开遇到 Ready/Paused 任务时，固定“任务执行”区显示“启动任务”/“继续任务”。第一次点击先回读服务的真实路径、步骤与执行身份，核对相同地图、绑定及版本且没有未保存几何改动，预览并明确确认；回读和确认本身均不触发运动。确认完成后，须第二次明确点击“启动任务”/“继续任务”才发送 start/resume。取消核对保留当前任务状态，重连不自动启动或继续。

“取消后续启动”只取消本次操作尚未发送的启动意图，不撤回已经受理、持久化或处于 Ready 的计划；需要终止该任务时使用“结束任务”。两类任务共用固定“任务执行”区的暂停、继续、结束任务、急停和复位故障。start 已发送后若响应丢失，只按原 requestId 查询，不再次发送；结果未知时核对工控机状态后重新决定操作。

地图几何、任务参数、原点或标定变化后，旧准备结果失效，需要重新上传。仅旋转视图或切换显示不会改变计划身份。循环任务的末端必须连接起点；往返任务通过原地转向后正向行驶实现。旧文件保留原请求容差（例如 0.15 m），并要求重新确认坐标；它不代表已经满足新精度目标。

坐标统一以工控机 ENU 为导航输入：X 东、Y 北，航向从东逆时针为正。地图文件保留原南/东轴，编译任务时先转换轴向，再应用一次地图绑定的旋转和平移；车标显示和示教用相反变换回到地图。Qt 的 Y 轴向下与用户旋转视图仅影响显示和鼠标映射，不改变任务坐标。点击、示教、保存、加载及常规/直线任务编译均保留 double 精度；修改点的其他字段、检查点停留/拍照选项或任务名称时，不再把未编辑的坐标、检查点距离或转向航向截成显示小数位。原最终 HTTP 已有三位小数保持原样，软件往返一致性不代表实车绝对定位或路径跟踪精度已验收。

标准导航仅更新控制配置版本时，相同原点与车辆标定的地图在导航空闲或任务结束、没有已准备计划时自动刷新控制版本，保留原点、地图变换和所有几何内容，随后重新编译上传即可。Ready、执行中、暂停或原点/标定不同的地图不自动刷新。

维护中心的“工控机维护”通过任务服务相同主机的 `18133/api/v1/management` 和相同访问令牌连接独立管理服务。可显式启动、停止和重启融合、导航、相机，读取融合/导航的重要参数白名单并按版本保存、应用。打开页面不写配置、不启动服务；保存不代表生效，应用必须通过任务空闲/停稳检查，重启并读回运行值后才能确认。活动与暂停任务不能用维护操作自动停止；先显式结束任务。若操作权被占用，可在空闲时点击“释放任务操作权”，按界面提示等待已知会话到期后重试，commissioning 最多约 10 秒；再次操作任务时自动重新获取。

导航参数中的 `endpoint_recovery.enabled` 以复选框显示，保存值与已核验运行值分别标为“启用/关闭”；`endpoint_recovery.max_offset_m` 为 0.10～0.50 m 的回位尝试上限，只有固定 `final_http / vehicle_footprint` 模式可启用。它不等于到点完成容差，也不在地图或本机配置保存另一份值。旧配置缺少字段时按关闭兼容，显式保存/应用才由工控机先备份并迁移。导航 `/configuration` 中的 `endpoint_recovery.evidencePolicy` 是只读算法说明，`absolutePositionVerified=false` 表示相对运动证据不能证明绝对位置准确。适用端点、运动证据和空间检查见 [导航说明](../src/tracking_node/README.md)。

任务状态沿用现有枚举，另读取可选布尔字段 `endpointRecovering`；旧服务缺省为 false，非法类型拒绝。首页运行状态显示“端点回位中”，偏移和暂停原因使用工控机同一快照；缺少运动证据、返回空间不足、恢复超时分别显示中文原因。暂停、结束过程及监视延迟继续独立展示，不能据回位标记声称已停稳。

服务按融合→导航启动，相机独立。停止、重启融合或应用融合参数前先停止导航；相应按钮会说明顺序条件，不通过自动停止活动任务来跳过检查。提交维护操作后，先查询该操作的结果，再重新读取实际服务状态，确认完成后才恢复后续操作按钮。响应丢失时只按同一操作 ID 查询；记录无法查询、查询超时或鉴权失败时显示结果未确认并重新读取状态，不自动重发原操作，不把旧状态或 HTTP 受理当成服务已完成切换。

上位机日志固定在程序所在目录的 `logs/`（当前工作空间为 `bin/logs/`），不受启动器当前目录影响，不回退到 AppData。每次启动一个 `tenco_<启动时间>_<进程号>.log`，统一记录关键操作、连接变化和错误；不另外生成审计或累加运行日志。默认单次上限 5 MiB，可设置 256 KiB～16 MiB；达到上限在同一文件保留最新半段。写入使用有界异步队列，重复消息限频，不记录高频运动命令，保留脱敏。

维护的导航状态页通过同一工控机地址的 `18133/api/v1/management/resources` 查看整机资源，每 2 秒更新，由已部署的管理服务提供，无需启动融合或导航。传感器仍从融合诊断读取；融合停止时传感器显示未知，整机资源继续更新。资源认证失败、接口未安装、连接失败及数据过期各有提示，过期值清空为 N/A。

## 3. 运行与异常恢复

- 人工暂停保留进度并立即发送独立停止请求，工控机按当前减速度平滑制动；例如速度 0.10 m/s、减速度 0.05 m/s² 时，指令速度降到零约需 2 秒，之后仍须确认实测停稳，不能把点击暂停或收到受理响应当作已经停车。待操作结果确认时禁用继续；匹配请求确认完成后立即刷新按钮，继续仍需明确点击，并由工控机重新校核坐标、实时位姿、反馈、停稳和请求有效性。传感器/位姿断流暂停则由工控机保留当前 execution，发零速等待新鲜有效位姿、实测反馈、停稳和捕获范围连续稳定至少 0.5 秒后自动续行；界面显示 `autoResumePending` 等待状态，人工再次暂停可取消自动恢复。中止结束当前 execution；再次作业重新准备计划。
- 手动输入只影响本通道；自动运行不检查手动操作。连接恢复不重放旧速度，自动故障恢复仍需显式任务操作。
- 首页停止只清除手动输入并发本通道零速；公共“任务执行”区的“结束任务”向 tracking 发送 abort，“急停”发送 estop，使自动任务故障并发零速。二者都会取消尚未发送的后续启动。“复位故障”也在该公共区域，仅当前状态为 Fault、状态可用于操作、底盘在线且反馈有效并实测停稳、没有待确认操作时可用；服务端还会检查有效位姿及故障是否已消除。复位确认 applied 后清空旧任务及上位机准备计划，回到 Idle；需要重新下发任务，不自动继续。复位软件故障不代表底盘实体急停已解除，实体急停应先在现场解除。
- 操作会话每 200 ms 续约。commissioning 当前会话期限为 10 秒、单次运动许可最多 3 秒；未配置时的默认严格值分别为 1 秒和 500 ms。客户端使用服务端返回的有效期并扣除通信往返耗时，许可仍绑定服务与状态版本。会话只保护后续任务写操作，过期不暂停正在执行的自动任务；网络恢复不会自动 start/resume。
- 无线任务状态的界面新鲜度为 1000 ms，位姿预览仍按工控机定位策略显示过期；标准导航启动不再因上位机预览晚到而单独拒绝，由工控机检查本机最新位姿、实测反馈和任务版本。状态过期不会被当作当前在线状态。
- HTTP 写入超时可能已经被服务端执行。客户端通过原 requestId 查询命令结果，不重发运动操作；prepare 结果未知、等待超时、连接中断或身份改变时取消串联启动，晚到的 prepare 结果与连接恢复也不会重新启动。界面显示“结果未知”时先核对工控机当前执行状态。
- 位姿流断开、无新序号达到配置超时、内容无效或超出单行限制时，客户端取消连接并退避重连；重连不请求历史样本，同一 bootId 的重复或倒退序号不刷新新鲜度。收到新鲜有序监视帧后，地图页自动清除仍属于该次连接故障的提示；仅连接成功、重放或积压旧帧不清除。监视恢复不代表定位已可导航，采样中断、任务错误及操作结果未知提示仍保留。旧服务缺少 `/pose/stream` 时明确报告 HTTP 404，不回退为低频轮询。`poseSource.requestTimeoutMs` 同时约束流建连及连续无新样本的等待时间；状态的 350 ms 新鲜度检查独立生效。
- `freshnessBasis=http_receipt` 的位姿使用服务 `sendMonotonicSeconds` 与本机单调时钟的相对进度检查传输积压，不跨机比较绝对时间；NTP 调整 `sendTime` 不会误判流时钟倒退。真正的单调发送时间倒退、无效时间和序号重放仍不能刷新位姿。旧 `source_time` 保留原发送时间检查。
- fusion/tracking 重启更换 bootId，底盘 WebSocket 重连更换工控机本地 connectionId；旧位姿、示教结果及相关请求失效。tracking 将未完成执行记为 Aborted/interrupted，重启不自行运动。
- 关闭程序前可取消未保存文件对话框；确认退出后停止本地客户端及手动发送，已启动自动任务继续在工控机执行。包含拍照 external_ack 的步骤仍需要外部业务确认，离线时等待并按步骤超时处理。

## 4. 检查点拍摄

停车及停留由工控机完成。启用拍摄的检查点产生 `external_action_requested`（reason=capture）事件，保持 Waiting；Tenco 的 ExternalEventCoordinator 只处理业务拍摄和事件确认，不生成运动速度。

相机调用 `POST /camera/photo`，期望 `{ "success": true, "path": "..." }`。调用前先原子写入事件 intent，拍摄成功先保存结果再发送 ack。记录位于 Qt AppLocalDataLocation 下 `checkpoint-actions`，文件名为事件 ID 的 SHA256；最多 4096 条，达到上限后停止新拍摄并提示归档。不要删除未完成任务记录。

照片响应丢失、程序在拍摄中退出、事件缺页或结果未知时不会自动重拍。此时固定“任务执行”区按需显示“核对拍摄结果”，核查相机实际文件后可确认成功或失败；确认绑定当前服务、任务、执行、步骤及事件身份，身份变化或失联即取消，不能误确认随后出现的其他事件，也不能覆盖已确定的成功或失败结果。取消对话框保留等待；人工暂停中可以确认，但车辆继续等待显式恢复。传感器自动恢复保留同一拍照事件和 ACK，不重拍或跳过未知结果；超时暂停须先核实结果并显式恢复，已登记的失败 ACK 不可改写，当前需结束后重新规划。

示教采样失败或请求结果未知时不生成示教点；确认停稳后可重新采样。采样结果必须匹配 fusionBootId，服务重启不能复用旧 captureId 的结果。

## 5. HTTP 接口

下列路径相对于 `/api/v1`。写操作使用 Bearer 认证；普通 tracking 写操作同时要求 `X-Operator-Token`，全局 estop 及下述绑定执行身份的 safetyStop 不依赖操作会话。生产非回环监听必须配置认证。服务 HTTP 正文上限 8 MiB；control/heartbeat 小包上限为小于 16 KiB；Qt 普通响应上限 1 MiB，任务回读上限 16 MiB，与服务存储文档一致；重定向禁止。64 位序号字段使用十进制字符串，禁止用 JSON 浮点数传输。

| 服务 | 方法和路径 | 用途 |
|---|---|---|
| fusion bridge :18131 | GET /pose/stream | 持续 NDJSON 位姿推送，每行一份同源快照，Tenco 的位姿入口 |
| fusion bridge | GET /health、/pose | 健康与最新位姿快照，保留诊断和兼容读取；Tenco 不用其替代推送 |
| fusion bridge | GET /diagnostics | 每 2 秒采样的原始传感器在线/RTK 质量与 CPU/GPU/内存/磁盘只读状态 |
| fusion | POST /captures；GET /captures/{captureId} | 有界异步静止采样、样本计数和离散度（采样口径见下文） |
| tracking :18130 | GET /health、/configuration、/status | 配置版本、就绪条件和任务快照 |
| tracking | POST /sessions、/sessions/{sessionId}/heartbeat | 操作会话和短时运动许可 |
| tracking | POST /tasks；GET /tasks/{taskId}?revision=1 | 整项计划上传、持久化和回读 |
| tracking | POST /control | start/resume/pause/abort/estop/reset_fault |
| tracking | GET /commands/{commandId} 或 /commands?requestId=... | 确定写入最终结果 |
| tracking | GET /events?after=...；POST /events/{eventId}/ack | 事件补读和业务结果确认 |
| tracking | GET /executions/{executionId} | 历史结果与中断记录 |
| tracking | GET /origin | 当前运行原点；旧 POST 单独更新返回 origin_managed_by_maintenance |

任务、标定和地图必须匹配 context 中 mapId/mapRevision/originRevision/frameTransformRevision/calibrationId/controllerProfileRevision。start/resume 还带 expectedStateVersion、motionPermit、validForMs。每次显式操作生成 requestId；同 ID 不同正文被拒绝。

暂停/中止向 `/control` 发送 `safetyStop:true`，携带 `cmd=pause|abort`、唯一 `requestId` 及已知 `bootId/taskId/revision/executionId`。认证和执行身份仍校验，该通道不要求会话续约或最新 `expectedStateVersion`；服务端持久化去重并优先排队。启动/继续不得使用该例外。未知响应只查询原请求，不再次发送停止意图；正常磁盘工作仍不可抢占，不能承诺任意网络或磁盘故障下的停止时延。状态 `measuredStopped` 只在新鲜实测反馈连续停稳时为 true，反馈过期时 `stoppedForMs` 为 null。

固定 `final_http / vehicle_footprint` 模式对明显孤立跳点或非法数值先归零并保留任务，异常帧不推进路径或改变转向锚点；可信邻域和原任务捕获范围内的新位姿、实测反馈与停稳连续稳定至少 0.5 秒后可自动续行。持续远处偏移不重建新基线。人工暂停取消自动恢复，坐标/设备身份/真实时钟错误仍不自动恢复。上述判断位于导航侧，不更改原融合结果。

`GET /pose/stream` 使用 `Content-Type: application/x-ndjson`，每行一个与 `/pose` 相同 schema 的 JSON 对象，位姿三值与原最终 HTTP 发送值完全一致。服务按原样本到达推送，Tenco 在数据到达时逐行解析；客户端的 50 ms 定时器只检查新鲜度、重连与示教状态，不限制接收为 20 Hz。流只发送订阅后的新样本，单行上限 64 KiB，累计流长度不受普通单次 JSON 响应 1 MiB 限制。连接沿用 Bearer 认证并禁止重定向。

pose 中 stateAgeMs、positionObservationAgeMs、headingObservationAgeMs 各自表达估计状态、真实绝对位置观测及航向观测的年龄。流客户端保留服务端年龄，并增加当前行组装、按服务端发送进度与本地单调时钟估计的新增积压和本地停留时间；不会将建连耗时或整个连接存续时间累加到每帧。此相对进度估计不能测出首帧已有的单程网络延迟。原 HTTP 不提供已接受绝对位置/航向观测的时间，桥接保留未知观测时间并标记 `absolute_observation_times_unavailable`，不能将发送时间冒充观测时间。在 `original_http / http_receipt` 模式下，`/captures` 按不同 HTTP 交付序号收集样本；其他模式沿用不同位置观测时间取样。两者均检查有效性、坐标版本、新鲜实测反馈、停稳、样本数量和散布，失败不建点。HTTP 收包样本不等于独立绝对位置观测，低散布也不证明没有固定定位偏差。

状态/反馈窗口统一 350 ms；RTK 非 FIX、低星或原始观测年龄偏大只标记降级，合法新鲜估计继续控制并平滑降速至 0.10 m/s；NaN、状态过期、未初始化及坐标版本不匹配仍不可用于控制。车标逐条更新有效位姿；无效时暗显最后位置。当前 commissioning 显式使用已确认的车身中心、固定尺寸、最终 HTTP 位姿及保守制动估计，允许在相应模式下执行任务；标定和定位误差仍保留未验证，不伪称实车精度或制动实测完成，也不放宽其他严格配置。

原点统一在“维护 → 工控机维护”启动/重启融合时确认（应用融合参数也走同一对话框）。首页只读展示工控机保存/运行原点，原提交按钮跳转维护页；“定位与控制”不再编辑本地地图参考坐标。确认保留原值不改变原点版本，修改则同步融合与导航配置并生成新版本，旧地图和任务失效；取消不写入、不启动。管理服务事务保存两份配置，启动后通过不可变参数快照和桥接 activeOrigin 读回确认，不能以仅保存磁盘代替生效。当前基线为 field-base-origin-20261027（30.2228148,120.0225781），每次运行使用工控机最新确认值。远程服务先启动融合再启动导航；相机可独立启动。导航进程启动无需等待 FIX 或位姿采集完成，任务开始仍要求有效实时位姿和实测反馈。停止/重启融合前先停导航。

## 6. 底盘 WebSocket 既有协议

手动和自动各自连接底盘，两端只发送：

```json
{"packet":{"cmd":"region","region":"cmd_vel","index":1},"msg":{"xvel":0.1,"yvel":0.0,"thetavel":0.0,"isRemote":true}}
```

`isRemote=true` 选择当前 Lua 的外部速度入口，不是上位机手动身份字段。无控制权申请、租约、epoch 或额外速度字段。IPC 在本地丢弃过期命令、只保留最新速度，连接变化后不回放旧命令；现有 Lua 接收超时逻辑保持原样。

任务状态使用 `controlChannels=independent`、`chassisConnected`、`chassisConnectionId`。后者只是本地连接标识。`measuredTwist` 来自融合编码器，包含 valid/ageMs/source=fusion-encoder；不伪造底盘控制权或锁存状态。Idle、Ready、普通 Paused 和终态不会持续发布自动零速；等待传感器自动恢复期间持续保持零速，反馈未知时不声称停稳。

维护页“导航状态”每 2 秒异步读取位姿服务 `/diagnostics` 与导航 `/health`、`/status`，仅页面可见时查询，不申请会话或执行控制。显示编码器、前后 RTK、IMU、RTK 卫星数/定位模式、最终融合输出、任务恢复状态及工控机资源。传感器显示阈值 1 秒，控制窗口仍为 350 ms；未知、不支持或无法读取的值显示 N/A。接口失败或诊断缓存超过 5 秒时清除旧在线状态，认证和地址沿用已保存的连接配置。

## 首页与地图显示

首页的定位状态、自动任务状态和“本段进度”为只读概览，不提供手动/自动模式切换；任务启动、暂停、继续和结束统一在地图页“任务执行”区操作。“本段进度”表示当前路径段，进入下一段后重新计算，不代表整项任务的总完成率。概览区分新鲜反馈、状态延迟和离线；延迟时保留的内容属于上次数据，不能据此认定当前位置、任务进展或已经停稳。底盘电池与数字速度继续独立显示，不替代融合定位和导航反馈。

两类任务共用工控机跟踪控制和当前生效的导航参数，区别在任务编排，并非两套精度模式。常规任务适合多点巡航，例如 `1→2→…→12→1`；每段按已有路径关系规划，若要返回或循环，必须明确编排回起点的路线。直线任务适合沿同一条示教作业线往返，检查点可分别选择去程/返程停留和拍照；已记录的中间点保留实际坐标，并不强制拉成数学直线，也不适合替代任意大转角的巡航路线。任务拍照仍需上位机协调确认。

左侧编辑区按“点位”“路径”“地图”分页；常用点位与批量生成放在同页，路径关系和网格显示单独管理。“地图”页的“坐标适配…”核对地图绑定及坐标变换，不修改全局基站坐标；新空白地图自动绑定当前有效原点，旧地图不会静默改绑。编辑模式下“记录车辆点”将当前车位移至视图中心，与直线任务记录车辆位置一样，向工控机请求 1 秒静止采样，成功后使用采样位置和朝向新增地图点；采样期间保持停稳，失败或地图、绑定、编辑状态改变时不建点，不回退成瞬时打点。输入坐标和地图点击仍按用户给定坐标建点。关闭编辑或任务进行中显示“定位车辆”，仅居中。实时位姿持续更新车辆显示，不会替换用户已选择的路线起点。默认地图目录固定为程序旁的 `maps/`，本机为 `bin/maps/`；加载及另存默认从该目录打开，新地图建议名为 `yyyy-MM-dd.json`，同日已有文件则依次使用 `-2`、`-3` 后缀。新建不提前写盘，快速保存继续写入当前已选地图文件。

“按序自动连接单向直线”默认关闭。开启后，输入、地图点击、记录车辆点和批量生成的新点，自动与编号在前的上一点建立单向直线，例如 `1→2→3`；已有点和路径不改变，加载地图不补线。自动连接不代表自动生成任务或回程，路线仍需加入任务队列。手动添加两点间的直线或圆弧关系时，可选择“单向”或“双向”，新建关系默认双向。双向关系只保存一份几何，反向规划沿同一几何反序行驶，无需再建一条反向关系。

常规地图点可设置“停留 (ms)”，范围 0～3600000，新建地图的默认值为 2000 ms（2 秒），与直线任务中间点一致；新增点采用编辑框当前值，可逐点修改，0 表示不增加停留。加载已有地图保留原点位设置，旧图缺失该字段仍按 0 处理。规划途经的点也遵守该点设置：到点后先按该地图点朝向对准并实测停稳，再由工控机计时；停留边界不会被连续路径合并。非循环任务的首点有停留时，先核对车辆处于原起点容差内并停稳，再对准、停留，不能从远处直接开始计时。循环任务在返回首点时每圈停留一次，下一圈开头不重复计时。直线检查点则在停留和拍照前，先按当前去程或返程的局部路径方向对准并停稳；中间点采用接下来行驶的方向，端点采用到达方向，返程不会复用去程采样朝向。两类任务仍使用工控机当前的角度与位置容差，旧已下发任务需重新编译下发才采用新步骤。

有非零常规点停留时，保存地图使用 schema 4，旧版上位机会明确拒绝，避免静默丢失停留动作；常规点停留全为零时仍保存 schema 3。旧 schema 1/2 保持原单向含义和零停留，不会自动变成双向，也不改变原地图坐标绑定。地图版本号与本机配置的 schemaVersion 无关。

点击已有点附近或在多选点之间切换当前行，会显示该点保存的坐标、朝向和停留值；只修改停留不会把点移到鼠标点击位置。换图或删除所选点时清除旧选择，修改其他地图或复用编号的点前须重新选中。加载地图会先完整检查字段类型、编号和路径引用，重复编号、悬空路径、自环或非法几何会明确拒绝并保留当前地图。完整任务最多 1000 步，循环间隔也计入；超限时在上位机提示，不下发不完整任务。

手动：按钮长按或 W/A/S/D → 原 WebSocket cmd_vel；松键发送本通道零速，断线清输入、重连不重放。首页的速度设置只作用于独立手动控制；“手动停止”清除手动输入并停止云台，自动任务使用地图页任务执行区的暂停、结束或急停。首页保持电池图标与数字速度显示，底盘反馈离线时保留原显示并标注状态延迟，不能据此判断车辆已停稳。PLC 云台为另一条 Modbus 链路，UI 应答成功不等于机械运动已经确认。

## 排查

测试进程以 `0xc0000135` 退出时，先将 Qt 和 MinGW bin 加入 PATH。状态日志 http=0、Operation canceled、device not open 时，检查 statusReadUrl、设备在线和超时；当前请求有超时及失败退避。WebSocket 代理异常时检查系统代理，ChassisClient 已使用 NoProxy。

`ping` 通只说明网络可达。工控机维护接口为 `18133`，返回 `401` 时应核对运行配置的 `network.authToken` 是否与工控机一致；导航 `18130`、融合 `18131` 随各自服务启动，服务停止时端口不监听。首页“底盘在线/状态延迟”对应底盘 HTTP 状态监视，不能据此认定工控机断网；远程启动仍按先融合、后导航进行。

视频异常先检查相机服务地址、实际预览接口的 multipart/x-mixed-replace 和相机 status 的帧新鲜度；通用 MJPEG 模式再核对 streamUrl。HTTP 可达不能证明采集健康。Windows 风格与自定义 QSS 导致 SpinBox 步进显示错位时可用 `-style fusion` 核对。

GUI 冒烟入口仅测试构建启用，使用回环配置并关闭真实设备服务。云台间歇失效、拍摄恢复偶发失败和现场验收缺口集中保留在项目说明；本地/仿真通过不等于实车通过。

## 各链路的业务频率

| 链路 | 现有频率/触发 | 本轮处理与数据量边界 |
|---|---|---|
| 视频MJPEG | 工控机当前预览15FPS，持续一条HTTP流 | 主要已测负载；每新增一个客户端会增加一份传输 |
| 控制器状态HTTP9999 | 响应结束后再等待100ms，8个字段合批 | 10/30改为单次调度，慢回复不积欠后补请求，失败退避和原失联停止处理保留；未实测真实控制器响应大小 |
| 云台Modbus502 | 每300ms，约3.33次/秒 | FC03请求12B、响应23B，纯Modbus约117B/秒，TCP/IP另计；点动/停止按操作触发 |
| 融合位姿18131 | 单条 `/pose/stream` NDJSON 推送，不逐帧发HTTP请求 | 当前写入帧加一个最新待发帧，覆盖旧待发帧；3秒写阻塞后释放连接；上位机逐帧校验、每次接收突发仅刷新最新显示 |
| 任务状态18130 | 单在途，支持序号/100ms等待；响应完成后等待 clamp(RTT,100,500)ms | 50ms计时器调度会量化间隔；1秒标迟、3秒运动快照、5秒监视连接；实际频率还受服务等待和RTT影响 |
| 任务事件18130 | 原每200ms，即最多5次/秒，即便没有新事件 | 有序号的服务且游标已追平时0次；新事件/分批/失败时按原200ms节流继续读取 |
| 任务health/configuration | health每秒；configuration约每5秒 | 配置年龄加RTT最多6秒才可用于任务/运动；显式任务操作、恢复、维护释放及原点/复位后强制刷新，旧代次回复不准入；离线或操作状态过期时跳过 |
| 普通命令结果 | POST结束或超时后，首次100ms，未解决再200/500ms | 写请求单发，结果不明只查询；安全停止结果使用独立100ms查询，不等待停止POST完成；10秒确认上限不因退避延长 |
| 操作会话heartbeat | 已显式获取会话后每200ms，最多5次/秒 | 不降低；保护后续API操作，自动执行不依赖上位机续约 |
| 手动WebSocket1202 | 按住非零控制时40ms，即25条/秒；松开零速 | 只留一个最新待发速度；本端积压/样本150ms到期或超过4096字节时断开，受阻零速立即断开；重连清队列，需重新操作 |
| 相机状态/设置 | 首页状态约2秒一次；维护面板显示且已读配置后约1秒一次 | 这些是小JSON；拍照/录像控制、设置读写按用户操作，无整段媒体回传 |

用户操作、任务上传、诊断、重连和其他程序另计。所有服务正常且没有新事件时，任务事件优化可以少至每分钟300次空HTTP查询；不能把5次/秒描述成5个IP包/秒，一次HTTP可能包含多个数据包、建连和挥手。旧服务若缺少可选lastEventSeq，继续原事件轮询，避免失去事件功能。

## 无线通信和积压边界

工控机普通HTTP已改为有界长连接：每连接最多64请求，首读4秒、后续读取及空闲5秒，响应写入3秒；每次重建解析器、独立鉴权，400及以上回复关闭。所有连接启用TCP_NODELAY。请求串行处理，迟到或重复异步回复不能答复后一个请求；停止后不再排入迟到回复。

Tenco将监视GET与会话、写操作及结果查询分开连接池，安全停止仍使用独立客户端；每通道单在途、总在途上限和写操作不自动重发保持。新增HTTP总耗时、发出请求、首次响应及发送次数统计；复用连接可能没有建连里程碑，这些偏移不能当作精确的无线单向时延。慢请求日志限频且不记录URL、凭据或请求内容。

位姿同boot的http_receipt时间进度跨重连保留，未见过的积压帧不能因重连重新变新鲜，重复序号也不延长期限；服务重启建立新的时间域。首次连接的绝对单向传输耗时仍未知。服务端应用缓存覆盖不能撤回TCP已经在途的字节，客户端继续按年龄显示延迟。监视容忍不改变工控机本地350ms位姿/反馈或底盘150ms命令期限。

手动速度队列使用本机单调时间，新的40ms心跳不能刷新最早未排空写入的年龄。10ms精确定时器及本端排空事件负责检查；应用事件循环的调度延迟仍会影响检查时刻。收到零速时可立即写就覆盖未发运动，已有本端积压则中断连接并明确显示尚未确认底盘停稳。该150ms是上位机本端保护期限，既有手动报文不含TTL，socket排空也不是底盘收包或停稳确认；不能撤回已进入TCP的数据。断开、显式停连及析构清空队列，自动重连不恢复按键和运动。

10/30后续批量流量采用工控机唯一`server.bulk_response_mib_per_second`配置（0～64整数，0关闭），旧配置明确按8MiB/s兼容，读取不覆盘，显式保存/应用时备份并迁移；上位机维护页读写这一字段，不另设本机默认。32KiB分块共享该预算，批量请求16个、并发发送4路、待发字节32MiB，停止响应独立编码4项，3秒总发送期限保持。源端读取大任务/历史与控制响应的耦合进一步减少，详情见[发送预算及业务分批](../docs/项目总览.md#2026-10-30-通信发送预算与业务分批)。

Tenco使用随机`X-Request-ID`关联受限的服务端阶段时长，只有回显匹配才采纳`Server-Timing`；本机单调RTT继续独立记录，不算单程延迟。诊断页增加复用同配置、同boot且独立年龄新鲜的TrackingClient health，陈旧时读自身只读接口。410事件恢复按100条分页逐页处理，冻结高水位、有限重试并拒绝重复游标，未完成不跳过实时事件。

## 无线只读测量

建议先停止首页预览再运行，避免测量期间形成两份视频流。该脚本只GET拉流，不拍照、录像、改设置、重启或发送运动；输出不含原始图像。

```powershell
python Tenco/scripts/measure_camera_traffic.py --url http://192.168.31.13:18080/camera/stream.mjpeg --seconds 15
```

工控机也可运行同一Python脚本，将URL改为127.0.0.1；同时对比可帮助区分本机出帧与无线交付。cadenceFps使用相邻完整帧到达间隔，应用流量包括首个缓存帧；样本很短时帧数/总时长和间隔FPS会有差异。网络异常/不完整JPEG明确报错，不把失败当作低带宽达标。
